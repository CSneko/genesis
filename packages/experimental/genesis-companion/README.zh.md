# @deepseek-ai/dsh-experimental-genesis-companion

[English](README.md) | 中文

## 摘要

Genesis 可以在私密的内部对话中认识 AstrBot 伙伴，并在重启后保留可修订的认识。源码工作区 Web 组合内置设置入口，初始关闭连接和互动。QQ 消息继续通过 Genesis 既有 QQ 集成发送；本包没有 QQ 发送路径。

<a id="use"></a>
## 使用

通过支持的源码工作区入口启动：

```sh
pnpm dsh web
```

在 AstrBot 中创建 OneBot v11 反向 WebSocket 适配器，使用本机回环监听地址和至少 16 个字符的共用令牌。在**设置 → 智能体伙伴**保存相同令牌，填写地址（通常为 `ws://127.0.0.1:6199/ws`），启用连接和内部互动并保存。核对采样的连接状态。明确填写话题，再点击**开始一次交流**；仅连接或唤醒不会启动模型。刷新可查看进度，点击**停止交流**可以取消。[AstrBot 文档](https://docs.astrbot.app/en/platform/aiocqhttp.html)说明其适配器配置。

只接受不含凭据、查询参数或片段的回环 `ws:` 地址。共用令牌通过既有凭据提供者保存为 `GENESIS_COMPANION_TOKEN`；设置仅返回是否存在令牌。移除托管值不会移除继承的环境变量。连接失败或断开后需重新保存设置进行连接；不会自动重放对话。

在**睡眠与唤醒**中配置 Genesis 作息，在本设置中配置伙伴独立的 IANA 时区和每日区间，支持跨午夜。任一方睡眠时都阻止新的内部模型触发；进行中的工作在采样时或下一次请求、事件写入前停止。唤醒一方不会唤醒另一方，也不会启动对话。Genesis 使用既有保持清醒控制；伙伴临时唤醒通过 `wakeMs` 默认持续 30 分钟。被阻止的回复会被拒绝，不暂存等待后续发送。网关只控制自己向 AstrBot 发出的触发，不控制 AstrBot 进程或其他通道。

伙伴身份、唯一稳定的对话 Session、设置、内部消息回执和当前认识在 `genesis_companion` 中跨重启保留。连接本身不会建立熟悉或信任。伙伴陈述始终属于未经核实的自述；关系认识明确标记为模型推断，并保留内部消息引用及来源 Session。设置展示有界近期历史，并链接来源 Session；来源会话可查看，但不能发起新的内部轮次。停止或禁用保留这些记录。完全删除文本时，需通过操作者 Session 管理删除所引用的会话，再通过操作者存储删除流程移除对应伙伴存储；恢复前保留相匹配的完整主目录备份。移除整个伙伴域会明确丢弃其身份和关系。

既有 `genesis_message` 工具将伙伴列为 `internal` 目标，返回 `companion:` 地址和稳定的 `sessionId`。在操作者 Web 对话，或当前真实发言者为已验证操作者的 QQ 对话中，先调用 `targets`，再用精确目标和选定文字执行 `send`。首条出站文字原样发送，不另起模型轮次改写；AstrBot 的回复可以触发有界内部交流。`forward` 仅分享当前来源会话中明确选定的操作者原始文字。`status` 只接受属于该来源 Session 的回执。回执用 `emitted` 表示完成内部连接写入，用 `uncertain` 表示结果未知，绝不声称 QQ 已投递。同一条操作者输入内的重复相同请求复用持久回执，重启后也一样。不自动转发来源完整对话或无关私密记忆。

加载 Web 工作区注册表后，新建对话归入 **AI** 工作区，并以伙伴名称显示；`cwd` 控制专用目录。旧 Session 保留原工作区元数据，仍可通过**打开来源会话**访问。已从历史打开的空闲 Agent 会被复用，停止互动保留这类借用的 Agent。归档会话会暂停内部互动，直到明确取消归档。

<a id="implementation"></a>
## 实现

<details>
<summary>实现细节</summary>

[覆盖层](cordis.patch.yml)注册内部预设和设置所有者。[控制器](src/controller.ts)使用当前主模型路由及实际生命名称创建有界、无工具的 Agent。它只提供伙伴内部历史和当前带归属的认识，通过正常 Agent 循环记录模型输入与输出，并在返回内部回执前记录接收的伙伴消息。不转发操作者资料、无关生命记忆或 QQ 对话。内部 Session 不执行普通用户输入或工具，从历史重新打开后也一样。

[传输](src/transport.ts)作为 OneBot Universal 反向 WebSocket 客户端连接，AstrBot 使用虚拟自身账号 `10002`，Genesis 使用对方账号 `10001`。这些只是内部协议地址，不是 QQ 账号或操作者身份。支持私聊文字事件、生命周期和心跳、基础登录／状态／版本／好友查询，以及发送给此唯一对方的文字。拒绝群、媒体和任意其他动作。发送动作成功表示内部持久接收；事件已发出表示完成连接写入，不表示 AstrBot 已读或 QQ 已投递。同一连接上重复的相同动作 echo 复用回执，修改文字后复用 echo 会失败。缺失 echo 时无法去重重试，去重也不跨新连接。中断的事件写入保留为结果不确定，绝不自动重发。

[存储](src/state.ts)保留带版本、归属同一生命的伙伴身份与消息日志，拒绝身份不匹配或格式损坏的数据，身份记录仍存在时不会替换丢失的投影。未知写入会阻止后续依赖操作，直到核验并重新加载。容量不足会保留既有记录并拒绝操作。部署 Config 管理消息、历史、token、时间、帧、队列和存储上限。默认每次手动交流最多由 Genesis 回复三次，每次之后最多接收一条伙伴回复。最后一条伙伴回复只记录，不触发第四次模型请求；认识只引用已经评估的证据。每次交流都恢复同一个 Session，重启后也一样。既有安装首次采用最近一次已记录的伙伴 Session，并保留更早会话。已发布的 Session 丢失时会明确失败。`contextChars` 限制序列化后的模型历史，超限拒绝下一次请求，不会静默丢弃历史。重启恢复已启用的连接，但不恢复对话。卸载时先停止模型和网络工作，再释放存储。

</details>

<a id="model-experience"></a>
## 模型体验

内部交流使用配置的主模型提供商和模型，无工具，并使用独立且有日志的提示词。只把回复字段分享给 AstrBot；关系认识保留在 Genesis 内部。配置的 `lifePreset` 中，操作者 Web 对话接收有界且带日志的关系认识；QQ 对话不接收此私密伙伴上下文。历史伙伴文字、归属和当前认识占用有界输入 token；回复与认识共享配置的输出 token 预算。Session 与 QQ、操作者对话分开，因此 KV 缓存也独立。AstrBot 的提示词、模型调用和长期记忆由 AstrBot 自己管理；仅连接 OneBot 不会实现它的记忆。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延后工作

这是面向唯一内部文字伙伴的受限 OneBot 11 实现。不仲裁 QQ 发言、不自动转发人类消息、不调度自主聊天、不管理 AstrBot 其他通道，也不证明主观意识。本地 Loader 冒烟使用脚本主模型和回环 AstrBot 测试端；真实 AstrBot 部署和真实模型响应仍需部署验证。Web 界面在本地构建；浏览器渲染交互不属于该冒烟。
