# @deepseek-ai/dsh-experimental-genesis-mail

[English](README.md) | 中文

## 概述

Genesis 可以接收文字邮件，自行决定阅读或回复、保存草稿并通过专用账号发信。工作区 Web 配置包含邮件设置，账号初始禁用。默认不限收件人、允许主动发送，每日额度为零表示不设置发送配额。睡眠暂停角色处理，后台仍继续收件。

## 使用

发件地址恰好匹配一个已保存的 Genesis 联系人时，来信通知会包含其称呼和与人物关系共用的人物 ID。这是操作者提供的地址关联，不代表发件人鉴权；匹配有歧义时不标识人物，操作者权限仍须满足配置的邮件鉴权。

通过受支持的工作区入口启动：

```sh
pnpm dsh web
```

在**设置 → 邮件**保存她的邮箱地址、账号用户名、IMAP TLS 主机名和端口、SMTP 主机名和端口，以及应用密码。IMAP 要求隐式 TLS；SMTP 支持隐式 TLS 或强制 STARTTLS。先保存连接字段，再保存密码，最后启用账号。默认凭据引用为 `GENESIS_MAIL_PASSWORD`；状态不返回密码，邮箱状态不保存密码，模型也不会收到密码。移除受管理密码不会移除继承的环境凭据。两个协议共用同一密码；要求 OAuth 的账号需要另一种传输实现。

打开 **Genesis → 邮件**浏览收件箱、拦截邮件、草稿、已发送、归档和垃圾箱。搜索覆盖发件人、收件人、主题和保留正文，结果分页。你在这里打开邮件不会算作 Genesis 已读。邮箱自动收信，打开的页面按配置的 `pollMs` 间隔自动更新（默认一分钟）；**收取邮件**请求立即进行一次有界同步。角色使用前需要学习 `genesis_mail`；普通操作者 Life 会话可以教授这个准确工具名。账号设置、工具学习、权限和成功使用是不同事实。

收件人范围可以不限，也可以限定地址或域名，与主动发信开关分别配置。每日额度按 UTC 计算，零表示不限。每份草稿只有一个收件人，正文不可变。回复引用本地来信 ID，并且必须发给实际发件人；Reply-To 标头不会重定向回复。SMTP 接受只表示发件服务器接受邮件，不代表对方收到。未知结果会保留显示，不自动重试；采取后续行动前先核查提供方。

在 **Genesis → 联系人**选择操作者并填写其邮箱。**设置 → 邮件**仅保留用于发件人验证的**可信收件认证服务**，不再单独设置操作者地址。启动时会将旧操作者邮箱并入已有操作者联系人，再清除旧设置；找不到操作者联系人时会停止迁移并保留原地址。首个 `Authentication-Results` 字段必须属于该服务，并报告与解析后 From 域名对齐的 DMARC 通过。仅当收件服务为每次投递前置自己的结果，并清除冒用其标识的伪造结果时，才配置该标识；否则留空，所有邮件按外部发件人权限处理。显示名称、仅匹配 From 地址、转发邮件和关系估计均不能授予权限。通过认证的操作者请求仍遵循现有沙箱、工具学习、审批和停止规则。

外部邮件处理只能访问自己的发件人／线程和自己创建的草稿，只能执行学习和邮件工具，并且只能向原发件人起草回复。普通操作者 Life 会话和通过认证的操作者邮件可以在配置的收件人权限内主动发信。执行时重新检查权限，重新打开旧处理会话不会授予操作者工具。来信通知只包含元数据；正文通过记录到日志中的工具结果显式读取。

正常醒来或**保持清醒**后分批处理待阅邮件；睡眠和仅供操作者交流的临时清醒不处理积压。邮件不会请求唤醒。暂缓的邮件到指定时间后，在下一次符合条件的机会处理。已打开且忙碌的处理会话会继续保持待阅，直到空闲；处理器借用空闲会话，不销毁浏览器持有的 Agent。

文件夹变更只作用于本地，不改变服务器文件夹或 IMAP 已读标记。永久删除本地副本前，先将邮件移入垃圾箱。不含正文的提供方和工具调用回执防止重新导入或重建。服务器邮件、处理会话日志、派生记忆和备份需要分别删除。整套备份或恢复前先停止运行时，并保持生命、邮箱与 Session 数据一致。已初始化状态丢失、归属不符、记录损坏或写入不确定时明确报错，不创建替代邮箱。

来信在通知角色、列出或读取前通过提示词注入审查，包括已认证的操作者邮件。发件草稿在 SMTP 提交前通过隐私审查：拦截私人真实姓名、住址和密钥等秘密，允许公众人物、公开企业地址和配置的邮箱地址。两种审查复用**知识库 → 决策模型**，支持其提供方或 System One 路由。发件审查失败会返回工具错误；修改内容后需新建草稿。审查服务失败时拦截该邮件，并为操作者保留诊断。

**拦截邮件**只通过操作者界面提供。角色不会收到被拦截来信的通知，不能列出、搜索、读取、回复或解除拦截。拦截副本经过垃圾箱再恢复也不会放行。第一版邮箱数据显式迁移为第二版并设为待审；旧运行时拒绝新存储版本，降级前需恢复匹配的升级前备份；先前已进入对话的内容无法撤回。审查请求和响应的 Session 事件保存在邮箱私有的 `reviews` 表中，不进入可搜索的对话 Session，删除本地副本时一并删除。模型审查可能误判，作为既有工具权限的补充。

<a id="implementation"></a>
## 实现

<details>
<summary>实现细节</summary>

[配置层](cordis.patch.yml)在 Genesis 旁挂载一个可选邮箱。[运行时](src/runtime.ts)负责有界 IMAP 轮询、归属生命的第二版存储、独立的角色注意状态、不可变发件预留和主模型处理。每个发件人／线程和权限级别拥有独立持久化 Session；通知和工具结果保留模型实际看到的证据。[传输层](src/transport.ts)使用 ImapFlow、MailParser 和 Nodemailer；解析前限制原始邮件大小，HTML 转换为保留的纯文字，不开放或执行附件。完整序列化状态与完整工具结果分别受预算约束。

存储和注入的所有者关闭前，先排空轮询、模型请求和已接受的工具操作。SMTP 提交前先保存发送预留；重启后保留未决结果为不确定。通知准入不确定时不重放。生命初始化标记可以发现整个邮箱存储域丢失；初始化和收件连接分别形成成长观察，都不授予工具，也不证明 SMTP 投递成功。

</details>

## 模型体验

学习后，`genesis_mail` 开放有界列表／读取、草稿／发送与本地整理操作。邮箱处理通知标识准确邮件，不提供整个收件箱，也不强制回复。普通主模型决定如何处理；睡眠期间不调用辅助模型读信。正文只通过工具读取进入角色对话；独立审查模型在私有审计 Session 中接收有界邮件头和正文。`refresh` 可以主动检查新邮件。每次处理机会具有可配置的输出、步数和时间限制，每个邮件线程使用自己的历史与 KV 缓存。学习、权限和实际服务器接受仍是独立事实。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延后工作

当前支持一个使用应用密码认证的纯文字 INBOX 账号，尚不支持 OAuth、附件、提供方文件夹变更、上传到 IMAP 已发送文件夹，以及投递／退信追踪。首次导入包含 INBOX 中的已有邮件；超大邮件会阻止游标前进，直到提高预算或将它移出 INBOX。UID 世代重置可能以新的提供方身份导入同一封实体邮件。不限收件人和发送额度不取消存储、推理、提供方或操作者资源限制。不确定的通知需要核查并由操作者显式处理，不自动重放。Loader 测试替换了外部邮箱服务器和模型响应；真实账号的 TLS 认证与真实模型行为仍需部署验证。
