# Genesis 人物与 QQ 对话

[English](guide.md) | 中文

## 变更

Genesis 添加可选的版本 1 `people` 状态和 `genesis-person` 消息来源。没有人物字段的旧生命记录仍可读取，生命 ID 和出生时间保持不变。旧版严格 Genesis 读取器会拒绝新写入的人物状态。不修改 SQL 模式或 Session 格式代际。QQ 召回遵循 `memorySharing`：生命覆盖层选择 `life`，允许 Web／QQ 共享记忆，单独挂载默认使用 `conversation`，按来源受众隔离；额外工具要求明确的 QQ 工具包权限。

新的模型人物数据使用 `qq`、`nickname`、`name`、`seenBefore` 和 `isOperator`，不再使用不透明的人物 ID。自定义情绪写入模型必须通过 `relationships[].qq` 指定人物，Host 将账号解析为未改变的持久化 `personId`。QQ 昵称变化或新的群 Session 不会创建另一个人物；原始 Session 日志保留既有归属信息。

QQ 策略保存现写入版本 3；版本 1 和 2 采用显式部署默认值 `groupAutoReply`，其默认开启。自动模式观察允许群的消息，不要求提及，由 Genesis 已配置的决策模型选择是否回复；私聊绕过此判断。旧版 QQ 策略读取器会拒绝版本 3。

工具包目录保存使用版本 2 并添加可选 `qqAccess`，旧条目在 QQ 中仍禁用。QQ 无需学习即可使用已注册搜索工具。按 Session 的 QQ 启用授权及当前发言者检查限制额外已学成员，旧启用状态不能授权这些成员。旧目录读取器会拒绝版本 2。

QQ 还需要附件及模型服务。媒体／引用插件记录和独立的第一版 QQ 决策设置／近期回执需要匹配的当前读取器；QQ 编辑不会修改共享记忆路由。解码前提、下载来源及删除方式见 QQ 指南。

## 迁移

1. 启用 QQ 前，停止当前生命写入进程，保存两个存储域、独立备份及原始 Harness Session。保持同一 `DSH_HOME`、路由和租约路径。
2. 按 [QQ 指南](../../../genesis/qq.zh.md)配置明确的机器人账号、令牌、允许的群及私聊对象，以及可选的已验证操作者 QQ 账号。绑定后不能悄然改变操作者映射。没有映射时，任何 QQ 账号都不会继承操作者身份或关系估计；生命范围的记忆共享独立于操作者绑定。
3. 带可选覆盖层重启。只有绑定的操作者实际发言后才复制旧有操作者关系估计。其他人物从没有关系档案开始。确认原生命身份，以及独立的群聊和私聊 Session ID。
4. 将自定义评估响应模式中的 `relationships[].personId` 改为 `relationships[].qq`，重新加载 Host 并刷新浏览器。确认同一账号可在另一个允许的群中被识别，同时不会显示私聊原始会话历史；已存记忆遵循所选共享策略。
5. 确认已配置 Genesis 决策模型。若需保留原先必须提及的行为，在“设置 → QQ 连接”关闭自动群聊判断；否则确认未回复消息仍可通过当前对话历史查询。在“设置 → 工具包”配置各包的 QQ 使用对象；仅操作者工具必须由绑定账号实际发言触发。
6. 降级前，应恢复完整且已验证的升级前副本和对应 Session。不要剥离字段，也不要把无法读取的身份替换为空生命。未确认的 QQ 投递不会自动重发。
