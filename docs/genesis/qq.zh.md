# QQ 对话与人物关系

[English](qq.md) | 中文

## 摘要

可选的 [QQ 层](../../packages/experimental/genesis-qq/README.zh.md)通过 OneBot 11，将已初始化的 Genesis 生命接入文本对话。每个群和私聊分别保留持久化的 Harness Session；同一个 QQ 账号在不同对话中始终对应同一个人物。关系估计不会授予权限。

## 从当前工作区连接

通过[觉醒流程](awakening.zh.md)配置并命名生命。单独运行 SnowLuma 等 OneBot 11 客户端，并自行登录独立机器人账号。两端使用同一访问令牌；凭据不要放入 Git 或聊天消息。

通过支持的入口启动当前工作区。Genesis 组合已包含 QQ 设置入口，初始连接关闭：

```sh
pnpm dsh web
```

1. 打开**设置 → QQ 连接**。保存至少 16 个字符且不含空白的访问令牌；既有凭据提供者以 `GENESIS_QQ_TOKEN` 保存，页面不会收到令牌值。
2. 填写机器人账号和可选的已验证操作者账号。正向连接填写 `ws://127.0.0.1:3001` 等本机端点；反向连接留空端点并设置监听端口，默认 6700。
3. 启用 QQ 连接，点击**保存并应用连接**。检查采样状态；连接失败时核对 OneBot 客户端和令牌，再次保存以重试。刷新可获取最新状态。
4. 在**对话准入**中填写允许的群和私聊账号并保存，用逗号或空格分隔。空列表拒绝对应输入；明确允许任何人私聊也不会授予主机权限。默认由决策模型选择是否回复群消息；关闭自动判断后才应用必须提及机器人的规则，操作者身份绑定不会自动允许私聊。

连接配置和准入策略独立于生命历史持久保存，在同一 `DSH_HOME` 下重启恢复。保存连接配置或修改令牌会先关闭旧连接并收尾工作，再重新连接。禁用连接会关闭监听和 QQ 自己拥有的 Agent；生命身份、对话绑定与发送回执仍持久保留。移除令牌会删除凭据提供者管理的值；若存在继承的环境变量或显式部署凭据，还需移除这些值以防回退。写入结果不确定时会停止依赖操作，直到重新加载已验证的存储。

只接受不含 URL 凭据、查询参数或片段的本机回环 WebSocket 端点。容器客户端应把 OneBot 端点发布到本机回环地址，再使用正向模式。适配器以 Bearer 令牌鉴权，检查每个消息帧中的机器人账号，并在正向连接断开后重连。它不会自动启用或配置客户端的 OneBot 端点。其他配置可在 Genesis 及生命预设旁显式加载本包覆盖层；上游 Harness 默认配置保持不变。

## 对话偏好与工作区

在 **QQ 对话偏好** 中填写附加提示词，例如“回复简短自然，通常用一到三句话”，再与对话策略一起保存。变更在下一次准入的 QQ 请求中生效；清空时也会写入明确撤销旧提示词的日志。QQ 以外的 Web 对话不会收到这些偏好，偏好不会授予权限。

默认上下文窗口为普通私聊 200,000 token、群聊 400,000 token、已绑定操作者私聊 500,000 token。操作者在群内发言仍使用群聊额度。自动压力压缩采用配置额度与模型实际容量中的较小值，并沿用现有触发比例、回复预留和余量。这些数值用于管理历史，不会扩展模型容量，也不保证精确 token 计量。摘要失败时保留当前可见历史，并在 Host 中报告警告。QQ 请求通过插件部署设置 `maxCompletionTokens` 独立限制包含推理的输出，默认为 16,384；更小的显式请求上限优先。在 400,000 窗口、默认 80% 触发比例及 65,536 token 余量下，输入压力阈值为 318,080 token，而非预留 256,000 输出时的 78,464。工具、图片及系统上下文均计入输入压力。此设置不修改 Web 或记忆模型的输出限制。既有 Session 重启后的首次请求前仍可能按旧日志中的输出预留压缩一次；下一条已记录的 QQ 请求使用新上限。

加载 Web 工作区注册表后，QQ 将独立目录注册为 **QQ** 工作区，并把对话关联到其中。机器人账号与群号或私聊对方 QQ 号共同确定对话路线，路线使用最新的 Session 绑定；会话名称采用群名或私聊对方当前昵称。每条准入消息到达时，私聊昵称从已鉴权消息帧刷新，群名通过 OneBot `get_group_info` 刷新。获取失败时保留原名称，初次获取失败则显示号码，后续消息会重试。名称不会改变身份或授予操作者权限。

QQ 会复用已由 Web 打开的匹配生命 Agent。断开 QQ 只释放 QQ 自己拥有的 Agent；从 Web 复用的 Agent 保持打开。

归档 QQ 会话后，同一用户或群的下一条准入消息会创建新 Session，旧 Session 保持归档。新绑定在接收消息前持久保存，后续消息和重启均使用最新绑定。人物身份、关系、长期记忆及历史会话归属保持连续；重放旧消息不会再次回复。取消归档旧 Session 不会让入站消息切回旧会话。要停止接收，请禁用 QQ 连接或从允许列表移除目标。主动发信仍拒绝只有归档绑定的目标，直到收到新消息或操作者恢复旧会话。

## 群聊选择回复与历史

在“设置 → QQ 连接”启用**由决策模型判断是否回复群消息**。使用所选 QQ 决策模型，结合真实提及、最近五条可见群消息、已鉴权发言者的关系估计、配置的公开角色倾向以及完全由当前群支持的兴趣判断。好感和兴趣增加回复意愿，但不强制回复；提及机器人时，如果实际在对其他人说话或回复会打断交流，也可以保持沉默。私聊绕过这一步，继续逐条进行普通回复。关闭自动判断后，可沿用必须提及的规则或回复全部已准入群消息。

在 **QQ 回复决策模型**中，可以明确复用 Genesis 共享决策路由，填写已注册的提供商／模型，或单独配置 System One／TypeSafe 端点、模型及 0～1 的阈值。专用密钥仅写入 `GENESIS_QQ_DECISION_API_KEY`；已注册提供商仍使用其原有凭据配置。保存 QQ 配置不会改变记忆决策设置或凭据。独立的第一版设置和有界近期记录在重启后恢复。近期列表显示来源群／消息 ID、时间、实际回复／跳过／失败结果，以及端点实际提供的概率与阈值。生成模型只返回布尔结果时显示**未提供概率**；失败不会变成 0%。刷新只读取记录，不重新执行决策。

决策请求和正式回复都会收到最近五条可见消息的有界页面，包含此前未回复的消息及角色的可见回复。`recentMessages` 可调整条数，`historyChars` 限制每个完整序列化页面，`historyLimit` 限制工具分页条数。过长正文会明确标记截断。每次决策请求与响应、已观察群消息及回复／跳过／失败结果均记录在该群 Session。决策失败不排队回复，并显示在 QQ 状态中；后续新消息仍可正常判断。

自动注入的近期消息不包含 Session 消息序号、QQ 消息 ID 或翻页游标。提供给模型的人物关系省略数值置信度；内部关系估计和决策回执仍保留审计数据。发言账号、昵称、时间、正文和必要的附件句柄继续提供。显式调用历史工具时，返回页保留翻页及消息引用工具所需的标识；已有存储消息和审计记录保持原样。

内置 `genesis_qq_history` 工具仅能读取调用者当前已启用、获准的 QQ 对话，包括较早未回复的消息。可选 `limit` 指定分页大小，以返回的 `nextBeforeSeq` 作为下一次 `beforeSeq` 向前翻页。不能指定其他群或 Session。QQ 私聊提供本私聊历史；普通 Web 会话不提供此工具。执行时重新检查通道策略和归档状态。工具结果使用普通带日志的执行流程，排除工具参数、工具结果和隐藏推理。它查询本地已经观察并保留的消息，不向 QQ 服务端补拉更早消息。

观察记录在推理前落盘，按消息 ID 跨重连和重启去重。中断或失败的判断不会自动重放，包括记录判断后、排队回复前崩溃的情况；需要时检查原 Session 并重新发一条消息。禁用 QQ 会移除历史工具注册。通过既有删除流程删除原 Session 时也删除这些观察和决策审计；仅遗忘人物不会清除原对话。队列或输入容量超限会明确报告，不会静默保留。

## 图片、视频、文件与引用回复

收到的图片／表情包、视频和文件消息使用既有不可变附件存储。正式回复在所选模型声明支持图片输入时收到规范化图片，以及有界 UTF-8 文档文字、`pdftotext` 提取的 PDF 文字、`ffmpeg` 默认在第 0、5、10 秒提取的视频帧。PDF／视频转换需要既有托管子进程服务和强制执行的只读沙箱。这是抽样视觉信息，不提供连续视频或音频转录、OCR 保证、Office／压缩包解码或任意可执行文件处理。不支持的格式、缺失解码器、模型能力不足和下载拒绝会产生可见说明，不会编造内容。成功保存的原文件仍可通过附件 ID 使用。

`genesis_qq_read_media` 读取当前对话已收到或生成的附件，即使当前消息未附带文件。只提供 `attachmentId` 或本对话已保留原附件的 `messageId` 中的一项；历史分页将附件元数据与可截断的文字分开。按消息查询最多读取 `maxMediaItems` 个附件，不会获取任意远程消息。如果旧附件未保留或字节已被清除，需要请发送者重发。`genesis_qq_send` 发送这类图片、表情包图片、视频或文件，发送数字 QQ 表情，或用已观察的数字 `messageId` 加回复文字引用消息。不接受收件人、Session、任意 URL 或主机路径；发送前重新检查当前通道权限及归档状态。动态表情使用原图片字节而非规范化静态图。文件上传、表情显示和媒体下载取决于 OneBot 客户端的接口支持；[NapCat 文件指南](https://napneko.github.io/develop/file)说明其客户端配置。文件上传确认如果没有消息 ID，仍标记为**结果不确定**，不能自动重试。

入站引用保留原消息 ID、发言者及摘录，与已鉴权的当前发言者分开。核验为同一对话后，未缓存引用中的媒体按既有下载限制接收，附件引用可供读取工具后续使用。适配器优先查本地历史，否则通过 `get_msg` 获取并检查相同群／私聊范围；无法核实或跨对话的内容会被隐藏。没有数字 QQ 消息 ID 的文件通知使用稳定的合成来源 ID，不能作为普通消息引用。引用、解码的文件内容和文件名都是不可信证据，不能证明身份或授予操作者权限。最近消息／历史分页保留未回复群消息的附件引用；决策模型看到有界标签，不会自动解读图片／视频。

部署配置限制准入：`maxMediaItems` 默认 5，`maxMediaBytes` 为每附件 20 MiB，`mediaTextChars` 为 12,000，`mediaTimeoutMs` 为 30 秒；既有附件图片条数／字节限制也会生效。`videoFrames`、`videoFrameInterval`、`videoFrameSize`、`ffmpeg`、`pdftotext`、`mediaGraceMs` 配置固定转换。`mediaOrigins` 接受精确 HTTP(S) 来源或最左侧 `*.` 子域通配符，协议及端口仍须相同。默认包含 `https://*.qq.com`、精确的 `https://multimedia.nt.qq.com.cn` 及配置目录中的 QQ 图片来源；其他客户端下载来源须明确加入。HTTP 媒体链接仅在对应 HTTPS 来源已获允许时升级到 HTTPS，不新增允许的主机。拒绝说明会指出来源或文件 ID 限制，不暴露完整下载链接。不接受重定向、URL 凭据或客户端本地路径。已鉴权客户端也可直接提供 Base64 字节，仍受字节及 WebSocket 帧限制。下载不携带保存的模型／OneBot 凭据。Session 日志保留引用和模型可见的解码内容，不复制带令牌的下载 URL 或 Base64 数据。

禁用 QQ 会注销媒体工具并等待或取消在途操作。删除原 Session 会删除引用／媒体审计及模型可见摘录；附件对象遵循既有共享附件存储的保留／删除规则，仅遗忘人物不会删除它们。专用决策密钥通过设置中的凭据操作删除。完全擦除还需通过操作者的存储删除流程清除 QQ 决策域 `genesis_qq_decision` 中的近期记录，并在检查其他引用后清除相关附件对象。

## 人物与关系

内部 `PersonId` 由 QQ 账号生成，仅用作 Host 的归属关联键。新发言者头部和模型人物表使用 `qq`、当前 `nickname`、已记录的 `name`（未知时为 null）、`seenBefore` 和 `isOperator`。同一账号在另一个群的第一条消息中也能被识别，昵称变化不会重置身份；这些显示标签不证明法定姓名、熟悉程度或信任。初次接触的人是陌生人，不会自动保留关系档案。有意义且带引用的交流可以建立档案；熟悉、好感、信任、安全感和依恋分别变化，各自保留置信度。熟悉不代表信任。仅提及或转发某个人不能改变与该人物的关系。

有界的参与者上下文包含实际近期发言者及其当前关系估计。重复交流按人物分别衰减。`people.maxPeople`、`maxEvidence` 和 `maxChanges` 限制保留和评估规模；超限会明确拒绝变更。[数据记录](data-model.zh.md)定义持久化方式。既有操作者关系只在显式绑定的操作者实际发言后迁入；昵称匹配不能确认操作者身份。在已绑定操作者的私聊中，日志里的 `participants.operator.qq` 将已鉴权账号与配置的操作者称呼和身份关联。群里匹配的发言者也会收到“妈妈”等配置称呼及 `isOperator: true`，但私密身份描述保持为空；其他账号使用同名昵称也不能获得该绑定。人物上下文预算不足时优先保留近期发言者，并报告省略数量。遗忘人物后，删除标记之前的接触记录不会重新生成已遗忘的身份认识。

## 提及

入站 OneBot 提及段及 CQ 字符串中的提及会保留为 `@QQ号`，只有提及而无其他文字的消息也支持。带日志的通道上下文标明机器人账号。被提及的账号与已鉴权发言者分开处理；提及他人不会转移身份或权限。

群回复中，`@12345` 等独立数字标记会转换为真正的 OneBot `at` 段，由 QQ 显示对应名字。`@昵称`、邮件地址和原始 CQ 文字保持普通文本，不支持发送 `@all`；私聊中的标记也保持文本。回复按 Unicode 文字和数字提及的写法计数分段，不拆开提及目标。每一段仍需独立的消息 ID 确认；结果不确定时不会自动重试。

## QQ 工具包权限

已绑定操作者的 QQ 私聊与已鉴权 Web 对话拥有相同的工具权限：所有工具包均可发现和启用，不受 `qqAccess` 限制。学习、对话内工具包启用、沙箱、审批和提供方检查仍然适用。以下 QQ 受众限制适用于群聊及其他人的私聊。

在**设置 → 工具包**中，为需要开放的包勾选**允许在 QQ 中使用此工具包**。新开放的包默认勾选**仅已验证的操作者可以启用和使用**；取消这个限制即可允许任何人。禁用的工具包仍不能通过 QQ 使用。旧目录按禁用迁移；保存的目录行使用版本 2，并兼容恢复第一版目录。API／配置条目使用可选的 `qqAccess: disabled | anyone | operator`。

已注册的 `web_search`、`web_fetch` 和 `genesis_speech` 无需学习或启用工具包，普通发言者也可使用，仍受提供方的查询数量、输出和网络限制。语音需要已配置的服务商凭据，可能产生费用；先生成音频，再通过 `genesis_qq_send(kind="file", asVoice=true, attachmentId=...)` 发送附件。新目录还包含 `qqAccess: anyone` 的“网页浏览”包（`browser-reading`）：学会并在当前对话启用后，普通发言者可使用 Playwright 的 `browser_navigate`、`browser_snapshot`、`browser_take_screenshot` 和 `browser_wait_for`。其他 Playwright、Chrome DevTools 和 Stagehand 操作即使属于广泛开放的工具包，也不向普通发言者开放。导航只接受不含内嵌凭据的 HTTP(S) 地址，浏览器输出不得指定 `filename`，因此不能直接执行脚本、填写表单、传输文件或管理标签页。浏览器状态由提供方管理：工作区的持久浏览器在对话间共享页面和登录状态，这些权限不会隔离它们；需要保密时应关闭 QQ 浏览器权限。已保存目录保持原样；可添加精确列出成员的浏览包，或调整已有工具包的使用人群来开放。

成员仍须已经学会并实际注册。`genesis_toolkit` 列出合格工具包，并仅在当前对话启用；任何人均可关闭工具包。仅操作者工具包的启用必须来自当前真实发言者绑定的 QQ 账号，每次执行受限成员也重新核对发言者，其他群成员不能借用之前的操作者授权。昵称、提及目标、引文、关系与检索历史都不能授予操作者权限。权限或成员编辑立即撤销执行能力。已注入且仍注册的工具声明在发言者和权限变化后保持存在，未获授权的调用返回错误。主动关闭工具包会移除其声明，除非另一个已启用工具包仍包含该工具。压缩上下文保留工具声明。此前因压缩而隐藏、当前仍符合条件的工具会在下次请求时自动恢复，重开同一 Session 后也会恢复，无需重新学习或启用工具包。已学工具提示与实际声明使用相同的筛选逻辑。执行拒绝会区分当前操作者缺席、尚未学习和缺少 QQ 工具包访问权限。分叉 Session 不继承启用状态，重开同一 Session 则从审计回放带版本的授权；没有 QQ 授权的旧启用记录不能解锁受限工具。

沙箱、工具审批和提供方权限仍独立检查。移除已学工具的最后一个所属包，不会让它自动通过 QQ 开放，仍须存在明确的 QQ 权限或内置声明。因此主机文件和 Shell 默认保持关闭。已学会的 `genesis_record` 和 `genesis_tasks` 是仅操作者可用的例外，无需启用工具包：QQ 会展示它们，并只在当前真实发言者就是已绑定操作者时执行。其他账号不能读写个人记录，也不能查看、创建或控制工作区任务。已绑定操作者的私聊使用上述 Web 规则。

## 跨会话发消息

`genesis_message` 允许当前已鉴权且绑定的操作者查找收件人、发送文字、转发自己的原文和检查回执，无需学习工具或启用工具包。普通发言者不能执行，即使直接调用工具也会被拒绝。输入接收与主动发送权限分开检查：`acceptPrivateFromAnyone` 不授予任何主动发送目标。在 QQ 插件上配置 `outboundGroups` 和 `outboundUsers`，两者默认均为空。例如，将以下内容保存为操作者补丁，在 QQ 覆盖层之后通过 `pnpm dsh web --patch <file>` 应用：

```yaml
- id: genesis-qq
  config:
    cwd: !!js dshHomePath('qq-workspace')
    outboundGroups: ['67890']
    outboundUsers: ['99999']
```

将示例账号替换为实际目标。`targets` 取这些列表与平台实时群／好友目录的交集，支持按名称或账号搜索及 `offset` 分页。名称是不可信标签；应使用返回的精确 `target`，操作者描述存在歧义时再询问。目标明确的清晰请求不需要额外确认。`send` 接受 `target` 和 `text`。`forward` 接受 `target` 及来源会话中已观察到的 `messageId`；仅支持操作者自己的纯文字消息，添加发言者标头并原样保留正文。有界来源投影保留最近 `historyLimit` 条原始消息；更早文字超出窗口时需要重新发送。不转发附件、平台提及，也不跨会话查找来源消息。出站内容使用普通文字段，因此复制的 CQ 代码和 @账号不会成为平台命令。

目标不需要先发过消息，也不需要有活跃 Agent。发送时会打开或恢复其稳定 Session，不提交模型任务；归档对话仍保持暂停。任何外部写入前，来源和目标日志都会记录精确投递计划。确认投递后还会向目标对话添加一条已记录通知，不触发额外回复。独立的第一版 `genesis_qq_messages` 域保存回执标识、来源／目标引用、内容哈希及确认信息，不再另存一份消息正文。`maxMessageReceipts` 默认为 10,000；容量耗尽时拒绝新发送，不丢弃去重证据。每个结果将完整 JSON 计入 `historyChars`，较长的确认编号列表会报告省略数量。

`status` 接受当前来源会话此前返回的投递 `id`。`confirmed` 表示每个分段都取得了 QQ 消息编号，不代表有人读过。`uncertain` 包括中断的预留、缺失的确认和部分投递。同一条操作者消息中的相同请求复用回执，包括重复的工具调用；重启绝不会自动重新发送日志中的投递。操作者稍后明确提出的新请求属于新动作。如果平台已确认投递而后续审计写入失败，应先检查 `status` 再决定后续操作。应将此日志与同一生命及来源 Session 一起保留，单独删除会破坏重放保护。删除消息内容需要移除相应来源和目标 Session；完整删除生命还应包含此回执域。

启用[智能体伙伴集成](../../packages/experimental/genesis-companion/README.zh.md)后，同一 `genesis_message` 目标列表也包含它的持久内部会话。该集成负责自己的睡眠检查、明确选文投递、有界回复和来源限定回执；QQ 允许列表及平台确认继续沿用既有含义。

## 记忆与投递

生命覆盖层选择 `memorySharing: life`，在 Web、QQ 私聊和群聊之间共享已存长期记忆及未过期临时记忆。原有来源归属继续保存在同一生命中；共享不会把所有发言者视为操作者，也不会开放任意 Session 原文。在 Genesis 插件上设置 `memorySharing: conversation` 可恢复来源受众隔离，单独加载插件时仍默认采用此模式。在该模式下，私聊记忆只在与同一人物的私聊中可用。群记忆仅用于原群对话。混合来源的解释必须满足每一个来源的限制。旧有操作者记忆保持私有，配置初始化的角色倾向可以共享。这些规则在提示选择、语义排序、联想和显式 `genesis_recall` 之前执行；模型措辞不承担访问控制。

QQ Session 默认包含遵循所选记忆策略的 `genesis_recall`、当前对话的 `genesis_qq_history`，以及已注册的 `web_search`／`web_fetch`／`genesis_speech`，无需教授或启用工具包。完成配置且已经学会时，`genesis_record` 和 `genesis_tasks` 在操作者本人发言的 QQ 轮次中可用。部署配置 `qqBasicTools` 显式指定内置工具名。其他对话的私有计划和兴趣不会注入。操作者管理仍使用已鉴权的本地 Web 界面。记忆共享由部署配置控制，未提供逐条记忆的共享编辑器。

输入消息 ID 和输出 Session 事件序号在入队或发送前持久化预留。只有每个文本分段都收到 OneBot 消息 ID 才确认送达。中断或只收到部分确认的投递保持结果不确定，重启后不会自动重发。手动重试前应检查原始 Session 和 `qq.receipt` 生命事件。重启后恢复同一生命身份和对话 Session；已发布的 Session 无法读取时会报错，不会创建替代对话。

仅供主机调用的 `LifeCore.forgetPerson` API 删除已保留的关系和源于该人物消息的记忆。它保留审计生命事件和原始 Harness Session；完整清除账号数据还需要操作者执行既有的生命及 Session 删除流程。

## 限制

适配器支持被动对话及当前对话中的显式媒体发送，不接受好友请求，不主动联系 QQ，也不提供关系管理 GUI。其他插件通道和操作者 Web 行为继续采用各自的权限。本地自动化测试使用脚本模型和 OneBot 测试端；真实 QQ 登录和消息交流需要操作者已登录的客户端。
