# Genesis 长时记忆

[English](memory.md) | 中文

临时摘要独立于本长期记忆管线并与其并存，参见[临时记忆设置、触发与过期](temporary-memory.zh.md)。

## 启用

Genesis 的可选 `memory` 配置启用语义回忆和已完成交流的独立批量记忆评审。决策和写入模型接收同一会话近期多轮的有界证据，包括当前已完成回复，不接收其他会话的对话历史。Web 生命覆盖配置默认使用 TypeSafe Jev 决策；单独的记忆覆盖配置保留已注册 Harness LLM 路由。Jev 请求与响应协议见[官方 System One API](https://api.typesafe.ai/redoc)。

在启动环境中将 `GENESIS_EMBEDDING_URL` 设置为完整的 OpenAI 兼容 `/embeddings` 地址，`GENESIS_EMBEDDING_MODEL` 设置为模型标识，`GENESIS_EMBEDDING_DIMENSIONS` 设置为向量长度，`GENESIS_EMBEDDING_API_KEY` 设置为凭据。不要把凭据放进补丁或 Git。先应用 Genesis 补丁，再应用提供的记忆补丁：

```sh
pnpm dsh --profile headless --patch packages/experimental/genesis/cordis.patch.yml --patch packages/experimental/genesis/cordis.memory.patch.yml --dump-config
```

配置转储只检查组合，不调用模型。配置好端点后移除 `--dump-config` 并传入任务即可对话。示例为两种辅助角色选择 `deepseek-official/deepseek-v4-flash`；修改 `memory.decisionProvider`、`decisionModel`、`writerProvider` 和 `writerModel` 可选择其他已注册路由。免密本地嵌入服务器可在自定义补丁中省略 `embeddingKeyEnv`。完全省略 `memory` 配置块会保留原有关键词检索和手动记忆行为。

## Web 配置

启用 Genesis 浏览器配套插件及记忆或生命叠加层后，打开“设置 → 知识库”。LLM 默认跟随 DSH 当前默认模型，关闭复用后可配置独立记忆写入模型。判断功能共享知识库决策模型，已有频道自定义保持独立。“云端配置”支持 Harness 提供方、OpenAI 兼容 `/chat/completions` 端点及 Jev `/v1/systemone` 端点；Jev 将返回的“是”概率与阈值比较。凭据保存在 Harness 凭据库。提供方检查准备所选路由，HTTP 检查通过有界 `/models` 列表验证模型，不发送对话证据。嵌入模型可选：未启用时对 Markdown／文本记忆进行文本检索，启用后配置 `/embeddings`、模型和维度以增加语义检索。嵌入测试执行一次请求，要求一个有限非零向量；`index` 可省略，提供时必须为数字 `0`。生命信息负责命名与成长。

保存的图形模型和嵌入配置优先于部署值，从后续操作生效，并在同一存储根目录下跨重启保留。每次评审固定使用一组模型路由和一个嵌入空间；变更端点、模型或维度后，会重建检索到的不兼容向量。失败时保留草稿和已有搜索结果。设置错误会显示受影响的操作和具体原因，不显示密码原文或服务端响应正文。并发保存通过版本检查拒绝；刷新并重新载入配置后再重试。移除已存密钥后可能启用环境变量中的备用值，免密服务须关闭认证。

“本地快速部署”通过固定的 Ollaya v0.18.0 运行时安装 [Laya multilingual](https://huggingface.co/convaiinnovations/laya-multilingual)，这是不生成文本的专用 System One 决策模型。固定校验和的[模型清单](https://ollaya.dev/v2/library/laya/manifests/multilingual)包含权重、分词器和决策组件（合计约 652 MiB）；Genesis 在启动前校验清单及每个文件的 SHA-256，重启时同样校验且不下载。本地路由通过 `/v1/systemone` 提交类型化问题并读取概率。自动安装支持 Linux x64（需支持 Zstandard 的 `tar`）和 Windows x64（需系统自带 `tar` 及对应的 [Microsoft Visual C++ 运行库](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)）；其他平台需提供兼容的 Ollaya `localDecision.binary`。安装仅写入租约旁的 `genesis-local-decision`，服务只监听回环地址并使用临时凭据。部署限额、清单地址及校验和、运行时地址及校验和可在 `localDecision` 中调整。停止和卸载只释放所属进程及文件，保留生命数据和已保存的云端决策路由。下载、校验、启动或类型化判断探测失败都不会切换到云端备用模型。该模型仅支持文本，上下文短于通用聊天模型，超长请求会明确失败。本地生命周期检查使用替身推理服务，不代表已验证模型效果或硬件兼容性。

非密钥图形配置分别保存在版本为 1 的 `genesis_embedding_settings` 和 `genesis_model_settings` Storage Domain 中，与生命共用写入租约。它们独立于生命快照及其 JSON 备份，部署备份应包括两个存储域和凭据库。无效或不兼容的配置存储会明确失败；配置写入结果不确定时，依赖操作会停止，直到完成可信重载，不会替换生命身份。

## 参与者身份

在记忆 → 记忆 → 你的身份中填写姓名和身份。生命的名字和这份明确填写的资料会进入有界记忆推理及角色上下文，新总结使用这些名字替代泛指角色。保存身份时也会改写现有记忆、习惯触发条件／回应和经历主题中的旧称呼；模型只能选择已有称呼片段，由程序替换为填写的名字，不能借此改写事实。技术术语、第三方人物和协议归属枚举保留原意。所有批次及向量更新成功后，资料与称呼修改才一起提交；`memory.identityRewriteLimit` 限制完整处理数量。冲突或推理失败会保留原资料和记忆，历史版本和会话日志仍保留当时的原文。

<a id="memory-time"></a>
## 记忆时间

正文区分普通事件时间和需要准确记住的日期。`{{time:YYYY-MM-DD}}`、`{{time:YYYY-Www}}`（ISO 周一制）、`{{time:YYYY-MM}}` 和 `{{time:YYYY}}` 表示普通经历，读取时相对显示。`{{date:YYYY-MM-DD}}` 用于证据明确的生日、纪念日、约定、截止日期，或明确要求准确记住的日期；其他日历精度也支持 `date`。不知道年份的每年生日或纪念日使用 `{{date:--MM-DD}}`，不会捏造年份。写入模型根据所引用事实选择是否保留准确日期，不以记录保存时间推断重要性。明确提到的时刻可以保留在日期标记旁。

写入模型会收到来源消息时间，以及使用 IANA `timeZone` 的时钟，默认采用主机时区。相对说法按所引用消息的时间解释，而不是按之后评估的时间解释。整理选中记忆时，模型使用中文生成正文，并在嵌入前增加一次写入模型调用，结合相同证据检查完整草稿语义。该检查为真正的时间表达生成标记、保留准确日期、修正无效标记，或明确写为时间不详；普通词语、姓名、年龄和版本号保持原意。程序仅接受完整草稿 ID 及检查后的正文，来源、类别和评分沿用原草稿。两次调用使用同一组固定模型路由、输入输出上限和整次操作时限，均写入日志。检查失败或遗漏条目会保留所选记录。即使模型省略，程序也会保留所引记忆中的明确时间标记。整理后的创建时间不代表原经历发生时间。

角色读取包含当前记忆正文和去重元数据，`date` 标记保持准确日期，`time` 标记相对显示。非陈述性提示词记忆保持普通正文；陈述性摘要模块还携带 ID、版本、读取层级、归属和置信度，不附带来源引用列表或历史版本。普通时间优先使用今天、昨天、前天，再使用本周、上周、本月、上月、经过的月数、半年前、去年和经过的年数，保持已存精度。相对标签描述读取时刻，稍后使用旧工具结果时应重新查询。管理界面和辅助维护保留完整记录与内部标记。主机只校验和渲染完整、明确的时间日期标记，普通正文、年龄、版本号和模糊日期不变；整理时由模型结合证据解释真正的时间表达。

<a id="personality-and-speaking-habits"></a>
## 性格与说话习惯

Life 叠加层启用 `personality: {}`。`personality.tendencies` 提供初始非陈述性自我记忆，`personality.speakingStyle` 提供初始非陈述性过程记忆，`personality.importance` 设置其现有记忆优先级，默认为 0.5。默认设定是体贴、好奇、愿意表达偏好、认真对待承诺、熟悉后逐渐主动的角色；表达自然温和，严肃讨论时直接，并依据情境分享和使用幽默。配置正文属于初始设定，不是记住的经历或经过测量的心理特质。

初始化通过系统事件和持久的一次性标记写入普通有来源记忆。某类别已有活跃的非陈述性记忆时保留该类别，不添加默认条目。重启、配置变化和重新启用均不会覆盖编辑或重新创建已删除的条目。省略 `personality` 只关闭初始写入，不关闭已有记忆；可在记忆 → 性格与说话风格添加、编辑、转换或删除当前倾向；记忆浏览器展示相同记录。容量不足或无效时间标记会明确拒绝初始化，不替换生命。

对话、情绪评估与审议在现有记忆预算内共用按优先级排序的活跃非陈述性记忆筛选；辅助输入限制仍可能省略完整可选条目，或拒绝超限请求。已退役习惯不进入自动关联和行为上下文。性格影响事件解释、选择和表达，即时情绪与关系估计调节其表现。条件习惯仅在匹配情境生效，当前要求优先于记住的表达风格，但不会改变授权。

独立记忆写入模型使用中文创建和修订记忆正文，同时保留 JSON 键名与枚举值。正文、经历和短摘要直接记录发生的事，不附加“以上均为群内玩笑”“未见现实承诺”等评语。必要的玩笑、角色扮演语境用“开玩笑称呼”“在小剧场中”等措辞融入具体事件；参与者明确的否认和纠正仍保留为其表态。该写法用于后续生成和整理，不自动改写已有记忆。它区分明确的未来教学与仅适用于一次回答、任务或角色扮演的要求。“这次简短一点”留在对话中；“今后严肃讨论时通常简洁一些”可以更新过程倾向，并记录用户归属和来源引用。临时情绪及角色自己的声明不确立长期性格。逐轮更新保留以往认识。空闲巩固保留配置初始条目和操作者条目，仅依据配置数量的独立已完成用户交流学习单独的条件习惯。不新增独立特质分数、性格模型调用或性格定时器；对教学和表达的语义判断仍依赖模型。

## 回忆与更新

随附的生命覆盖层选择 `memorySharing: life`：同一生命在 Web、QQ 私聊与 QQ 群之间共享已存长期记忆和未过期临时记忆，包括此前保存的条目。来源人物、对话、历史和归属保持不变；共享不确认事实，也不授予工具权限。提示词、显式回忆和辅助记忆选择使用相同策略及现有输出预算。单独加载插件时默认使用 `memorySharing: conversation`，沿用原有来源受众限制。操作者可通过补丁选择任一模式，无需改写已存记录。原始 Session 历史、附件、操作者身份描述、计划和工具权限仍遵循各自的访问规则。

当前会话的对话就是短时记忆。陈述性长时记忆保存经历、陈述和自我知识。

已记录提示词保留非陈述性记忆，并提供有界的知识领域索引、事件摘要和相关参与者画像。领域概览采用有来源的摘录，目录浏览展示结构化路径。每条摘要使用独立的日志模块，话题变化不会清除旧读取内容。`memoryChars` 按渲染后的模块计费。关联预算按进入提示词前的候选读取记录计费，包含元数据。省略条目和未分类记忆仍可检索，不要求选择唯一项目或会话类型。

AI 使用近似主题或相关词构造非空查询，主动调用 `genesis_recall`；已知记忆 ID 仍可用于查询，生命模式在显式学习前即可使用此内置工具。全文检索统一大小写与全角字符，对中英文分词，并使用 BM25 按部分关键词、短语匹配和多关键词覆盖度排序。当前正文、摘要与主题的权重高于历史说法。已配置的语义结果通过倒数排名融合加入关键词排序。配置的共享策略、类别和时间过滤在排序前执行。嵌入服务失败或超时时，仍可返回关键词结果并记录主机警告；没有关键词结果时则报告检索失败。调用方取消仍会停止检索。临时摘要使用相同的全文排序和共享策略，保留现有过期规则。工具返回有界的 `genesis-recall-v1` 对象，包含当前 `entries`、`alreadyPresent` 标识和可选的临时解释。每条读取携带记忆 ID、内容版本、读取层级、正文、归属、置信度和读取指纹，不包含来源列表和旧版本；完整序列化结果计入 `resultChars`。仍在上下文中的当前读取不会重复提供；全文可以满足摘要请求，已保留的摘要仍允许之后读取全文。压缩改写或移除内容后可以重新读取，普通压缩正文不作为可靠的读取凭据；来源和历史继续保留在存储和管理界面。非陈述性习惯以当前正文的普通文本行进入提示词，仍属于不可信的候选信息。缺少分类的旧记录中，过程类仍视为非陈述性，其余类别视为陈述性。

使用 `genesis_recall` 的 `action: directory` 和可选 `path` 浏览领域及直接子目录；`action: browse` 按 `type`、`path` 或 `person` 筛选摘要，通过 `offset` 分页。搜索接受近似词或已知记忆 ID，`level: full` 读取详情。人物过滤支持准确姓名或稳定人物 ID，同名不证明身份相同。各视图保持配置的共享策略。

缺少组织信息的旧陈述性记录仍可检索：明确经历按事件读取，其余按 `unclassified` 读取。正常记忆写入和手动编辑可以设置组织信息，保留原始来源引用。已经存在的组织备份继续执行身份检查和删除清理，启动时不创建新的组织备份。降级前请阅读[升级指南](../upgrade-guide/v0.2.2-rc.1/genesis-declarative-memory/guide.zh.md)。

“知识库 → 记忆与情绪模型”提供“自动重试次数”，共用于记忆决策与写入、情绪、兴趣、决策、手动整理和空闲巩固的推理请求。默认在首次请求失败后最多额外尝试三次，设为零可关闭。保存值覆盖 `memory.maxRetries`，并在重启后保留；旧模型设置未保存该字段时沿用部署值。每次只重试失败的推理请求，保持已捕获的路由和证据。网络故障、HTTP 408/429/5xx、临时提供方故障和无法解析的 JSON 可以重试；认证、提供方明确报告的额度错误、配置、输入输出容量、Token 截断、语义校验和存储失败不自动重试。`memory.retryDelayMs` 默认在两次尝试间等待 500 毫秒；全部尝试共享原有 `memory.timeoutMs` 与取消信号。每次实际发出的请求均留有审计，耗尽次数后报告最终失败，不重复执行生命状态写入。嵌入和模型列表检查沿用现有行为。

辅助模型输入和完成响应在记忆发布前记入日志：已注册 LLM 路由使用可忽略的 `plugin:genesis/memory-call` 记录，独立 HTTP 路由使用包含完整非密钥请求体的 `plugin:genesis/model-http` 记录，不记录认证头。记录只保留在来源会话中，不进入聊天上下文，也不驱动恢复；不了解 Genesis 的读取器保留并跳过它们。

`memory.batchTurns` 默认累积四个完整交流回合后评审一次；不足四轮时，在最后一次回复后空闲 `memory.batchIdleMs`（默认 180000 毫秒）补评审。新输入会取消空闲计时，下一次完整交流结束后重新安排。各会话独立积累，同一会话的定时与满批触发合并，失败批次保留证据，等待新交流、明确重试或重新打开会话，不无限定时重试。设置 `batchTurns: 1` 保留逐轮即时评审。

`memory.windowTurns` 默认八轮，为本批新交流补充同会话最近已完成的上下文；新交流多于窗口时仍完整保留。排除未完成轮次、被中断回复和注入上下文。序列化对话超过一半 `memory.inputChars` 时先缩小新交流批次，再逐轮移除较早上下文；单个新交流仍超限则明确失败，不跳过证据。`newSourceSeqs` 标识本批所有新消息，决策还接收参与者、消息时间和当前时钟。手动生成仍立即使用所选回复及其之前的有界交流，不等待凑批或读取后续交流。

批量模式从 Session 投影恢复完整回复和已评审位置。可忽略的 `plugin:genesis/memory-batch` 记录仅在成功评审后推进位置；失败不消耗证据，生命提交与其去重标记仍原子保存。进程在生命提交后、位置记录前退出时，以相同批次标识重试，不重复写入记忆。首次启用批量模式时，以已有完整回复的末尾为起点，不自动回填历史；之后重新打开会话会继续未完成批次。该记录独立于只供审计的辅助模型记录。

每个自动批次进行一次决策，判断新增证据是否值得整理。决策提示词考虑日常经历和标明归属的角色扮演互动，不将其视为已证实的现实事实；分类与习惯校验由独立写入模型负责。Jev 将对话作为 `state`，使用命名的 `noul` 问题，并将 `answers.remember.noul` 与配置阈值比较。不更新时不调用写入模型或评审阶段的嵌入，回复前的关联检索独立执行有界嵌入工作；需要更新时，独立写入模型接收同一对话窗口、检索候选和有界非陈述性记忆。检索记忆、近期经历与非陈述性记忆共同使用完整写入请求的剩余预算，计入参与者、限制与 HTTP 编码，并按此顺序整条选择；过大的记录跳过，不截断新对话或改动未提供的记忆。写入模型只能引用实际提供的记忆 ID。可复用的知识、长期人物事实和自我认知会在经历之外单独提取。知识和人物视图按各条记忆的主要内容分类。经过验证的新增、修改、删除计划引用实际对话序号；用户陈述条目只能引用用户消息，助手内容保留为模型推断。用户介绍保留为标明归属的陈述，明确教授的持久习惯或人设可保存为非陈述性记忆。计划与轮次去重标记一同提交。内置首次问候不作为用户证据。

`maxImplicitMemories` 和 `memoryChars` 限制每次选择的非陈述性记忆，不限制已保存记忆的总数或总字符。`maxChanges`、`inputChars`、`outputChars`、`maxTokens` 和 `timeoutMs` 限制辅助工作。自动评审可以跳过字段或引用无效的单条草稿，将其余有效的新增和更新一并保存。主机记录被拒绝的草稿，并保留该批计划删除的所有记忆。如果没有有效的新增或更新，评审失败，证据留待重试。计划外层结构无效、模型输出超限或截断、向量不兼容都会终止评审。记忆失败保留已完成聊天回复的成功状态，在对话旁单独提示，用户可继续交流。聊天与知识库显示失败阶段及安全的错误码、原因，包括 HTTP 状态、模型终止原因或校验字段。写入响应校验还显示字段路径、预期类型及实际类型，区分字段缺失、`null`、字符串、对象和数组；未保留输入类型时不猜测。缺少必需的 `changes` 数组时明确提示，即使没有条目改动也应返回 `"changes": []`。已知类别与动作列出允许值，UUID 等字段说明所需格式；不回显字段正文、未知字段名或原始响应。重试也保留自己的错误，包括轮次证据已被替换或不可用。记忆与知识库页面还显示已评估轮次、完成时间，以及 Jev 决策的更新概率和本次阈值，包括无需更新的结果。诊断仅描述当前运行进程中的最近评估，重启后不恢复；不包含凭据、对话正文或服务端原始错误响应。批量模式可重试待处理的完整交流而不生成另一条聊天回复，重新打开会话可恢复证据。逐轮模式仍要求保留最近失败轮次的实时证据；开始新轮次或重启后需要新证据。失败不写入完成标记；存储或备份错误仍可能发生在更新已提交之后，须先检查再重试。提交前会检查取消，已接受的主写入仍会完成排空。

已注册的辅助模型调用默认使用 `memory.reasoningEffort: auto`：本次捕获的模型明确支持 `off` 时选择该档位，否则保留其默认值。此策略适用于记忆决策、写入、巩固及情绪推断；聊天设置独立。使用 `provider-default` 可沿用提供方行为，也可指定模型公布的精确档位，例如 `low`；不支持的显式值会在发送前报错。Jev 与专用 HTTP 路由保留各自的协议设置。`memory.maxTokens`（默认 4096）按提供方规则覆盖推理与最终输出。`max-tokens` 失败会报告实际推理档位，即使 JSON 可解析也拒绝写入；可降低辅助推理档位或增加 Token 预算。使用修正后的配置重启后，可在记忆页面点击“立即巩固”，重试保留的待处理证据。

<a id="memory-accessibility"></a>

## 可访问性与回忆强化

生命覆盖层启用熟悉度和遗忘。新的陈述性条目从 `initialFamiliarity`（0.25）开始。类别半衰期受重要程度和有间隔的回忆延长，基础值为经历 30 天、知识 90 天、自我 180 天和程序性记录 120 天。熟悉度只在命中条目之间调整排序，模型看不到该值。省略 `memoryDynamics` 时按普通相关性排序。

已提交的成功 `genesis_recall` 搜索为新返回的当前记忆增加 `recallGain`（0.25），同一实际用户交流最多计一次。自动线索、浏览、重放和 `alreadyPresent` 确认均不强化。间隔至少 `spacingDays`（默认一天）的有效回忆延长半衰期，由 `maxReinforcements` 封顶。编辑摘要保留熟悉度计时，正文、归属或置信度变化时按新认识计分。满分的条目进入现有巩固流程，形成习惯仍需独立用户证据。

启用 `memoryDynamics.forgetting` 后，Genesis 在启动或下次读取生命状态时移除低于 `forgetBelow`（0.03）的普通记忆。自我记忆、非陈述性记忆、操作者手动创建的记忆、进行中或暂停目标引用的记忆、含精确日期标记的记忆和重要程度达到 `protectedImportance` 的记忆豁免。首次启用时给旧条目新的保留期，并可继承此前的回忆证据。已提交的回忆和遗忘事件记录关联条目，不复制正文。历史 Session 消息和独立导出遵循各自的保留规则。

## 情景经历、以往认识与关联回忆

正向决策后，写入模型可在 `changes` 之外返回 `experience`。摘要、主题、置信度和所引用的对话序号描述有意义的交流，主机从引用推导会话身份及事件时间。情景经历是具有 `MemoryExperience` 元数据（`sessionId`、`startedAt`、`endedAt`、`topics`）的陈述性情景候选记忆。若交流仍在延续同一事件，模型可扩展已提供的同一会话近期经历，时间间隔由 `memory.experienceWindowMs` 限制，默认 1,800,000 毫秒。自动写入模型通过 `recentExperienceIds` 接收可用的同会话经历 ID。主机可以跳过无效的经历草稿，同时保存同批有效的新增和更新。经历、派生记忆、`experienceIds` 关联和评估标记一同提交，并受 `maxChanges` 限制。只返回 `changes` 的旧写入格式仍然有效，不会自动把旧对话转换为经历。

模型生成的内容、类别、分类、重要程度、置信度或归属变化时，旧认识作为 `MemoryRevision` 保留在 `history` 中，包含原始来源、`recordedAt` 和 `supersededAt`。时间表示系统何时持有该认识，不代表客观真相或陈述在现实中的有效期。重建向量和回忆不会提高置信度或产生新版本。历史版本计入存储上限。明确删除会移除该条记忆的内容和版本；删除经历还会清除其他记忆对它的引用，来源会话消息与审计事件仍保留。

每次接受真实用户输入前，关联检索在 `associationChars`（默认 2,000）内选择至多 `associationLimit` 条记忆（默认 3）。检索使用关键词和已有兼容向量，每次输入最多发一次嵌入请求。设置 `associationLimit: 0` 可关闭。`memory.associationTimeoutMs` 默认 1,200 毫秒，超时可用关键词结果或记录不可用提示，聊天可继续。显式回忆仍可补齐向量，并使用自己的超时。旧说法命中时提供当前内容。请求仅记录变化或新需要的记忆模块，并对保留的 Genesis 记忆区和回忆结果共用 `memoryContextChars`（默认 12,000 字符）。已记录的替换把过时或超预算内容移出模型上下文，同时保留原始事件及工具调用配对。

“记忆 → 记忆”展示经历时间、关联经历 ID 和可展开的以往认识。搜索覆盖当前内容、历史、主题和准确记忆 ID。适用的非陈述性条目提供完整行为正文，不参与熟悉度计算。

<a id="automatic-habits-and-idle-consolidation"></a>
## 自动习惯与空闲巩固

启用 `memory` 后，新评估保存的记忆会排入持久化整理修订。所有实时 Agent 空闲达到 `memory.consolidation.idleMs`（默认 60,000 毫秒）后，使用已保存的记忆更新模型与嵌入服务执行一次整理。每次最多考虑 `batchLimit` 条近期完整记录（默认 20），占用不超过一半 `inputChars`，为请求包装和反馈分组预留空间，较早记录仍可回忆。整理保留来源经历与操作者编写的条目，推导标明归属的认识，并为接受的更新保留版本。整理不会生成聊天回复，也不会唤醒角色执行外部任务。原对话记录准确的辅助输入与响应。重启后，待处理任务仅为审计恢复来源 Session，完成后释放自行恢复的 Agent；来源持久化缺失或不可读时明确报错。

学习得到的 `MemoryHabit` 包含适用情境、条件响应、启用标记与真实用户事件引用。形成习惯需要至少 `minHabitSupport` 轮独立且完成的用户交流（默认 3 轮）支持同一种行为。批量评审保留各条引用用户消息的原始回合，重启后仍可恢复。缺少独立回合标记的旧批次记录仍按一组证据计数。AI 重复陈述、同一轮的多次手动保存，以及缺少已完成轮次证据的历史记录均不增加支持次数。明确的用户教导仍可在普通评估时进入非陈述性记忆。推断习惯属于程序性、非陈述性的模型推断；后续纠正可以停用习惯，习惯不授予工具权限。停用习惯不进入提示词指导，仍可搜索和查看历史。编辑会接管当前内容并清除自动习惯元数据；转换为陈述性记忆会移除行为影响，并阻止巩固重新启用该条目。编辑、删除或转换学习得到的习惯还会将此前的用户支持标记为已覆盖，自动学习需要新的支持交流，不能立即用同一证据重新生成。

“记忆 → 记忆”提供自动巩固开关、立即执行及最近结果和具体错误。开关跨模式、跨重启保存，关闭后保留待处理证据，仍可手动执行。自动整理默认开启，成功后以 `cooldownMs` 间隔至少 300,000 毫秒，失败后以 `retryMs` 间隔至少 60,000 毫秒；同一待处理修订达到 `maxFailures`（默认 3 次）后停止自动重试。新证据或手动执行会重置该修订的重试预算。成功或空计划会消耗该修订，不会因自身输出再次排队。用户开始交流时取消推理并保留待处理任务，超时则消耗重试预算。计时器释放会取消并等待模型请求和自行恢复的 Agent 完成清理，然后才关闭存储。设置页保留安全的失败阶段、代码与消息，重启后仍可查看；刷新“记忆”以采样后台进度。

提交同时检查待处理修订和所有提供的记忆版本；并发编辑或删除会丢弃过期计划，原始来源保持不变。这是有预算的启发式学习与归纳，不代表人类记忆、主观体验或通用自主调度。每次最多增加一次受共享推理重试上限约束的写入操作和 `maxChanges` 次嵌入调用，并受现有推理、提示词与存储预算限制，无需新增模型角色。

## 当前会话总览整理

在已完成回复的“记忆”弹窗中选择“整个对话”，点击“总览整理当前对话”。来源必须是有权访问且已打开的生命会话。主机等待当前轮结束，再对最近一次已提交的上下文压缩替换消息之后的真实用户与助手聊天文本取快照；没有压缩时使用全部聊天。压缩前原文和压缩摘要均不参与。关联记忆仅选择来源全部属于该 Session 压缩后交流的记录，含压缩前或其他会话来源的记忆不参与且保持原样；没有压缩时保留全部会话关联记忆的选择策略。会话投影在重启后恢复相同范围，未提交替换消息的失败压缩不截断。压缩后尚无用户交流时明确提示继续对话，不回退读取旧记录。排除工具、推理、辅助推理、系统消息和注入上下文，不读取附件。证据不受搜索、近期轮次或预览数量截断；完整请求满足 `memory.inputChars` 时只执行一次写入操作，否则由独立写入模型依次读取全部分段，超长单条文本也会拆分并保留完整 Unicode 字符，通过简洁临时提要进入最终规划。请求大小包含已捕获的参与者、时钟，以及 HTTP 路由的提示词和完整编码请求体。

临时提要始终属于模型推断，只保留通过校验的原始聊天或记忆引用，不修改记忆。根据提要制定的计划只能写入陈述性、模型推断条目，不能确立用户原话或行为习惯。`memory.overview.maxCalls` 默认允许包括最终计划在内的 64 次操作，不计每次操作的有界重试。`memory.overview.timeoutMs` 默认给整个总览 300,000 毫秒，独立于普通记忆审查的超时。`memory.overview.requestTimeoutMs` 默认给每次模型请求尝试 60,000 毫秒；卡住的尝试会被取消，并按已保存的重试次数针对同一段证据重试，不重置整个总览的截止时间，也不在该次重试中重复已完成的分段。每次调用仍受 `memory.inputChars` 限制，但使用独立的 `memory.overview.outputChars`（默认 128,000 字符）和 `memory.overview.maxTokens`（默认 16,384 Token）。`memory.overview.maxChanges` 默认允许含可选经历在内的 64 项变更。`memory.overview.maxReferences` 默认允许每份提要或条目引用 10,000 个不同的聊天序号或记忆 ID，每条变更记忆合并后的持久化来源事件也最多 10,000 个。重复引用先去重再计数，不截断不同来源。每次提要请求明确列出允许引用的编号。引用无效或缺失时，可针对相同证据进行最多 `memory.overview.maxCitationRetries` 次纠正生成（默认 1 次）；纠正计入 `maxCalls` 并共享原有总时限，不会使虚构引用获得有效性。这些部署限制可在 `cordis.yml` 的 `memory.overview` 下配置；普通逐轮记忆仍使用较小限制。提要无效或过大、指令无法容纳、调用次数耗尽、取消或超时都会明确失败，不产生部分记忆修改。

当前记忆及其历史修订在整个生命的 `maxStateChars` 与 `maxRecords` 预算内保留完整来源列表。已有短列表仍可读取；执行原 100 个来源限制的旧读取器会拒绝扩展后的记录，降级前应保留已验证的升级前备份。

独立写入模型跳过决策模型，自行决定保留、合并、更新、删除或新增。它只能变更提供的会话关联记忆；未压缩会话的共享记忆也可能包含其他 Session 的证据；压缩后的整理排除混合来源记忆，无关或范围外的记忆受到保护。保留通过不返回变更表达，合并引用所提供的记忆 ID 或聊天序号。仅基于记忆的综合仍属于模型推断，不能提高置信度。最终条目无效时逐条跳过并在主机日志中警告，其余有效条目仍可提交；只要有条目被拒绝，就保留所有原计划删除的记忆，避免丢失来源信息。如果剩余条目均无法保存，请求失败且不写入完成标记，可以重试。JSON 或计划外层结构错误、嵌入服务失败、取消和存储失败仍会停止操作。主机在原子提交内再次检查所有选中版本与完整集合，来源被修改、新增或删除时拒绝过期计划。稳定请求 ID 保证失败或结果不确定后的重试幂等，重启后同样有效；更新保留以往认识与来源。重读旧对话不会新增习惯支持回合；准确请求和响应保留在审计中，不生成聊天回复。

<a id="selected-memory-organization"></a>
## 整理选中记忆

在“记忆 → 记忆”选择至少两条记忆或过往经历，点击“整理选中记忆”。结果条数可自动决定，也可指定精确条数，上限受选择数量与 `memory.maxChanges` 限制。已保存的更新模型使用 `m1`、`m2` 简短引用，由程序绑定到所选记忆版本；生命事件 ID 不能作为选择引用。模型仅整合这些版本，此操作不经过决策模型或空闲调度器。选择上限受 `memory.organizationLimit` 与一半 `memory.inputChars` 限制，超限时整体拒绝。每条结果必须引用选中记忆，所有选中记忆均须被覆盖，置信度不得高于所引来源的最高值。结果保存为带嵌入的陈述性模型推断，不成为已验证事实或自动学会的习惯。

所有结果与所选旧记录的删除操作，随 `memory.organized` 生命事件原子提交。原始生命事件证据保留，存续记忆会移除指向已删经历的关联；整理事件记录所选版本与结果到来源的对应关系。独立持久化维护 Session 记录准确的辅助输入与输出，不生成聊天消息。请求使用带品牌的 `MemoryOrganizationId` 跨重试保留身份，已提交请求在重启后返回相同结果。来源已修改或删除、无效引用、嵌入失败、提交前取消或模型输出错误均保留旧记忆，不发布部分结果。界面失败保留选择与结果条数，发生版本冲突后应刷新并重新选择当前版本。不自动触发选中记忆整理。

## 简短摘要

陈述性记忆写入时，正文附带 `summaries.brief`、`summaries.medium` 和 `summaries.detail`。在写入响应中，经历对象继续用 `summary` 保存正文。简略、中等、较详三档分别最多 40、60、120 个 Unicode 码点，每档保留归属、否定和不确定性。自动关联通常呈现中等版，明确询问时间、原因或条件时使用较详版。回忆工具接受 `brief`、`medium`、`detail` 和 `full`，`summary` 仍是中等版的别名。旧条目在预算内使用原短摘要或正文。生命覆盖层启用可选的 `memory.backfillSummaries`，每次在独立写入调用中补齐一条命中的旧线索。

记忆和整理预览显示简略摘要，通过“查看全文”可读正文。“修改摘要”编辑简略版，留空时清除生成的摘要。“生成摘要”使用已配置的独立写入模型及现有限额。主机将推理记录在独立 Session 中，拒绝过期或无效的结果并保留原记录。`genesisMemory/refreshMetadata` 同时重新生成陈述性分类。编辑正文会清除原摘要，自动实质修订会把旧摘要随原始来源保留。与旧运行时共用升级后的数据前，请阅读[升级指南](../upgrade-guide/v0.2.2-rc.1/genesis-memory-retention/guide.zh.md)。

## 手动记忆管理

在“记忆 → 记忆”中选择知识、人物、事件或未分类。知识目录与人物画像独立分页，分类和人物筛选先于记忆分页执行。尚未绑定身份的同名人物保持为独立画像，选择画像可查看其来源记忆。“新增记忆”和“编辑记忆”支持组织分类、目录路径与涉及人物；只修改组织信息时保留原归属和来源引用。

“记忆 → 记忆”独立于知识库配置，按时间从新到旧分页浏览全部已存记忆，非空搜索无需调用模型即可按相关度检索当前正文、摘要、主题、历史和精确 ID，并提供新增、编辑、删除，以及陈述性和非陈述性记忆转换。`MemoryKind` 表示这两类记忆；`MemoryDraft` 包含内容、类别、分类、重要程度和置信度。直接录入不调用模型或嵌入服务。新建条目标明为操作者输入并记录哈希来源事件。编辑直接替换当前字段，保留来源引用和已有历史，不新增修改事件或历史版本；文本变化时移除向量缓存以待检索时重建。转换保留原文、标识、来源和兼容向量，不新增历史；手动删除也不新增修改事件。有界的当前状态证据排除集合，防止已手动停用的习惯从相同旧证据再次形成。编辑与转换都受非陈述性数量和提示词大小预算约束。

每条已完成的助手回复提供“记忆 → 选择分类 → 生成并保存”，原有自动评估继续启用。此明确请求跳过决策模型，检索相关候选后调用独立写入模型，结合有界的同会话对话窗口，将有来源的改动保存到所选分类，不允许删除记忆。没有适合长期保留的信息时会显示未改动结果。私有可重放投影定位所选回复和对应的真实用户输入，支持后续轮次以及同一对话重启后的操作；单独的内置问候不作为证据。模型输入和响应通过既有辅助记录记入日志。同一回复和分类已提交后重复请求不会再次调用写入模型或重复保存。

新建草稿在失败重试间保留客户端 UUID。编辑、转换和删除检查界面显示的 `updatedAt`，并发变更会在提交前明确拒绝；刷新后再编辑最新版本。失败保留草稿或条目并显示具体诊断。删除移除当前记忆及其备份副本，来源会话消息和追加式审计事件仍保留，不会抹除原始对话。存储或备份失败可能发生在主数据提交后，须先检查再重试。

## 持久化与本地备份

既有生命存储在不同会话之间共享身份、人设记忆和长时记忆，不合并上下文。记忆记录保留来源事件引用、分类、归属和可选嵌入缓存。端点、模型和维度共同标识嵌入空间。新建和更新的向量会持久保存；历史或不兼容缓存会在搜索时按需重建。搜索目前扫描有界的本地向量集合，不依赖外部向量数据库。

每次主提交还会写入仅所有者可读写的独立备份。`backupPath` 可覆盖默认的 `${leasePath}.backup.json`；该文件是提交清单，组件保存在同级 `${backupPath}.d/` 目录。组件通过临时文件、文件同步和原子替换写入，随后发布清单。成功提交后，删除记忆会从主存储和备份中移除其旧正文、版本及向量组件。恢复副本必须包含清单、完整组件目录及两个主存储域。参见[存储布局](data-model.zh.md#life-storage)。

备份失败可能发生在主存储已经提交之后。Genesis 会停止依赖状态的操作并报告不确定结果，重启前应检查两份数据。主状态缺失但备份存在时，Genesis 拒绝创建替代生命。请停止写入并保留两份数据。[备份读取器](../../packages/experimental/genesis/src/backup.ts)支持旧快照和拆分备份，会检查引用摘要，并用 `stateSchema` 校验重建的生命数据。通过已配置的 Storage Domain 后端，将经校验的完整生命数据作为旧版 `states/life` 记录恢复；下次启动会发布拆分组件。仅备份清单不能替换 `genesis.json`，其同级组件目录不可缺少。未知或损坏的主状态不会被静默替换。

## 验证与限制

免密 Loader 集成验证独立模型角色、同义语义检索、重启连续性、会话隔离、本地备份，以及对无效证据和向量响应的拒绝。真实提供方调用需要部署凭据，这些测试未验证实时服务。分页存储限制单个组件大小，启动时仍加载完整生命数据，记忆推断不是已核实事实。持久工具学习与首次账号配置/命名流程见[首次唤醒](awakening.zh.md)。独立的[情绪评估](emotion.zh.md)可复用这些模型路由，自主唤醒调度仍未实现。
