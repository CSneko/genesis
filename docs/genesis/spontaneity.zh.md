# Genesis 自发认知

[English](spontaneity.md) | 中文

## 摘要

Spontaneity 让 Life 主模型关联近期对话、记忆、模拟情绪和兴趣，保存一个想法，或仅因好奇而尝试。念头不必成为目标，不必产生作品，也不必分享给操作者。

## 启用

工作区 Genesis Web 默认启用自发认知。Genesis → 念头可管理保存的念头、预算及停止当前探索；也可在此暂停。处于[睡眠](sleep.zh.md)或临时清醒时，不运行自主探索。以下补丁用于显式组合。

使用持久化的工作区 Web 组合，并配置命名、记忆和审议。通过受支持的入口添加可选补丁：

```sh
pnpm dsh web --patch packages/experimental/genesis/cordis.spontaneity.patch.yml
```

补丁设置 `genesis.config.spontaneity: {}`。显式组合省略它会禁用该模块；工作区 Web 可在念头页面暂停。追加 `--dump-config` 可以检查配置组合，但不会运行模型。沿用相同 `DSH_HOME`，以保留同一个生命和念头。

真实操作者 Life 交流后的安静时段提供一次机会。普通模式和 QQ 通道不会触发。进程必须保持运行；无聊计时可提供后续空闲机会，但没有离线探索或冷会话唤醒。同一来源事件在重启后也不能触发另一次机会。空结果和失败机会同样计入滚动每日限额。

## 无聊驱动的空闲机会与主动交流

启用情绪与自发认知时，轻量计时器每 `boredomCheckMs`（默认 60000）检查一次无聊，不调用模型。清醒、没有用户工作与待处理输入且无聊达到 `boredomThreshold`（默认 0.35）时，可获得新机会，无需再来一条用户消息。间隔随无聊升高而缩短，受 `boredomMinIntervalMs`（默认 300000）、`boredomMaxIntervalMs`（默认 1800000）和 `idleMs` 约束。空结果、失败和中断都计入已有每日预算。来源事件和凭据持久化；没有可用的操作者 Life 会话与模型路由时，不创建机会或唤醒冷会话。

内部联想可用 `genesis_socialize` 发现明确获准的在线目标，并发送一条原创短消息。QQ 只公开独立部署清单 `proactiveGroups` 与 `proactiveUsers`，默认均为空；`outboundGroups`、`outboundUsers` 和熟悉程度不授予自主发送权限。每次机会最多预留一次发送，跨目标共用 `socialCooldownMs`（默认 3600000）和 `socialMaxPer24Hours`（默认 3）。先持久预留，再通过现有 QQ 文本发送与回执流程执行；不确定结果计入限额，重启不会自动重发。此工具仅在已接纳的内部联想可执行，普通聊天与冷会话不能借用权限。不能自动转发私有历史或发布作品。

## 选择与回访

主模型通过日志接收有界的近期真实对话和已保存念头，并使用普通 Life 上下文。她可以回忆记忆、不产生新念头、保存想法、暂时放下、放弃，或选择一次短暂探索。配置中的二元决策端点不会替她选择念头或创建目标。

启用后，`genesis_thought` 在 Life 模式中属于先天工具。`list` 在当前标题和正文中搜索，提供有界分页，并返回当前对话的来源事件 ID。编辑包含标题、内容、原因、引用的生命事件和 `revisitAfter`（ISO 时间或 null）。提供已有 `id` 会跨对话更新同一个念头；省略 ID 会创建新念头。已有标题不能重复创建。`save`、`rest` 和 `drop` 不会启动工作。`delete` 要求已有 ID，删除当前及历史念头正文，同时保留不含正文的重放凭据。

`explore` 仅在内部联想期间被接纳。模型结束这次联想后，才启动单独的探索轮次。好奇本身就是充分理由，不要求活跃目标。`promote` 将念头关联到已有的活跃自主目标，主模型须先通过 `genesis_plan` 创建该目标。选择念头或建立计划都不能证明已经行动。

主机选择已到回访时间的暂存和休眠念头。回访时间只控制检索资格，不是闹钟。后来的真实交流提供另一次机会，让她继续、改变方向或停止。沉默不会降低长期兴趣。

## 私有工作与预算

每次机会拥有独立的 Life Session，使用既有 Agent 循环、来源对话最近记录的主模型路由，以及来源对话沙箱上限与部署策略的交集。它不加入用户的工作区对话列表，也不会把助手文字发送到 Web 聊天或 QQ。其持久化 Session 仍可供操作者检查。文件可以保存到个人目录，学会的 `genesis_record` 可以保存文字。保存念头或作品不会自动发布或发送。

工具学习、工具包启用、沙箱授权和操作者停止仍然有效。联想阶段允许念头、回忆、计划及受限的主动交流工具。探索阶段额外允许配置中准确列出的同步完成工具，默认为 `read`、`write`、`edit`、`genesis_record` 和 `genesis_toolkit`。未学习工具仍然不可用。探索阶段排除委派、后台任务、消息发送、调度和 PTC 执行；浏览器工具需要部署显式加入允许清单，并遵守原有学习和工具包启用要求。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `idleMs` | 60000 | 对话空闲后的安静等待时间。 |
| `maxDurationMs` | 180000 | 包含评审的整次机会期限。 |
| `maxOutputTokens` | 50000000（50M） | 主模型、辅助调用及重试共同预留的最大请求输出 Token。 |
| `maxPer24Hours` | 6 | 滚动二十四小时内的机会次数。 |

念头页面按 M token（1M = 1,000,000 token）显示和编辑总预算，默认 50M，可设置更大的值。`cordis.yml` 和设置接口中的 `maxOutputTokens` 仍使用整数 token，范围为 1～9,007,199,254,740,991；已有保存值保持原单位与额度。主动认知不额外设置单次输出、请求次数或工具调用次数上限；主模型使用其路由配置或服务声明的默认输出上限，服务未声明时由剩余总预算限定。整次机会期限、每日机会次数、工具授权与停止控制继续生效。

模型实际输出较少时不会退回预留额度。输入 Token 受既有上下文限制，但不计入此输出额度；这不是精确的总账单上限。额度耗尽会在下一次调用前拒绝依赖工作。`contextChars` 限制序列化后的念头和近期对话选择；`maxRecords` 与 `maxStateChars` 限制完整念头存储。`experienceImportance` 控制情节凭据的重要性。

新的真实用户输入会中断内部工作，让用户交互优先。存储已经接受的进度仍然保留。首版在空闲机会中切换，不会为了新念头放弃正在执行的用户任务。插件停止时先取消并排空所属 Agent，再关闭存储。

## 经历与恢复

只有属于已结算探索决策的真实助手和工具结果进入兴趣评审。联想、候选生成和计划本身不是探索证据。既有兴趣阶段规则仍要求独立探索和后续回访，才能形成长期偏好。情绪评审可以评价有来源的私有结果，但不能把它当成人际接触，也不能修改社交关系。简短情节凭据关联实际结果事件和来源 Session；生成的主张仍是带归属的解释。

版本化的 `genesis_spontaneity` Storage Domain 在 Genesis 生命租约下保存念头投影、编辑历史和机会凭据。应将其与生命存储、来源 Session 和个人文件一起备份；单独的生命 JSON 备份不包含念头。已初始化存储缺失、生命身份不符、记录不兼容或损坏会明确失败。写入结果不确定时，后续念头读取和效果会被阻止，直到验证并重新加载。

启动将未结算的预留标记为中断，将探索中念头转为休眠。它不会唤醒内部 Session，也不会重放外部行动。先检查已记录 Session 和外部回执，再通过后来的机会选择继续同一念头。停用该选项会保留历史，并阻止内部冷会话执行工具。早于探索决策的运行时无法读取新的 `purpose: exploration` 值，应使用兼容运行时及完整存储。

删除念头不会删除来源 Session 日志、情节记忆、作品或外部备份，它们有独立删除路径。容量耗尽保留已有记录并拒绝新增写入；保留的重放凭据填满存储时，需要导出或提高配置限额。

## 验证范围

Loader 集成使用脚本模型以及真实工具、Session 持久化和存储，验证文件创建、有来源的兴趣与情绪更新、取消及重启连续性。这不证明真实提供方的创作质量、精确模型账单或浏览器兼容性。私有探索没有自动发布路径；念头页面提供有界管理。
