# Genesis 睡眠

[English](sleep.md) | 中文

## 概述

工作区 Genesis Web 默认启用睡眠和[自发认知](spontaneity.zh.md)。通过 `pnpm dsh web` 启动；设置 → 睡眠编辑持久化作息，Genesis → 念头管理私有念头和探索预算。Life 会话横幅显示当前状态及唤醒控制。不加载 Genesis 的普通 Harness 配置保持原有行为。

## 作息与控制

作息使用 Asia/Shanghai 时区。默认周一至周五 09:00–12:00、14:00–18:00 睡觉；周末全天清醒，包括调休上班的周末。每个边界在配置时间前后五分钟内采样，且不会跨越相邻区间。采样结果持久化，重启不会重新抽取。设置可以修改每周区间、偏差、临时清醒超时、豁免日期及问候开关。

2026 年官方放假日期免于睡眠，依据[国务院节假日通知](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)。日历未覆盖的年份暂停自动睡眠并显示提示。部署方可以添加额外豁免日期；未来官方日历需要更新。显式关闭节假日豁免后，每周作息可以在任意年份运行。

仅在实际睡着时，经过身份验证的操作者发送“快醒醒”等短消息，才会交给现有决策模型识别唤醒意图。临时清醒允许操作者交流和请求工作，包括多步工具执行，仍遵循正常的意愿与权限规则；自发活动保持暂停。困倦或起床气只是可选表现，提示不会强迫她反对请求。默认十分钟没有新的操作者输入就继续睡觉。

操作者发送精确命令 `g#保持清醒`，或点击对应 Web 按钮，无需决策分类。她会保持清醒直到下一个独立睡眠区间，允许正常的主动活动机会，也不会被诱导产生起床气。临时唤醒不会推迟本次睡眠区间的自然结束。操作者的停止控制始终有效。

## 消息与问候

睡眠暂停 QQ 中的 Life 回复和自主活动。允许接收的 QQ 私聊先持久化排队，再处理媒体；正常醒来或保持清醒后，按收到顺序分批送入会话。临时清醒不会清空积压。群消息不积攒。投递前重新检查当前允许名单。持久化确认不确定的投递保留为不确定状态，不自动重放。UI 显示待阅和不确定数量。

在计划入睡或醒来的边界，她可以根据已有关系估计发送一次简短问候，也可以保持沉默。临时唤醒及其再次入睡不触发问候。问候仅通过 QQ 发送，不会挑选 Web 会话投递。QQ 要求明确授权的私聊主动发送目标、当前接收策略允许且连接可用；没有符合条件的 QQ 目标或连接时不发送。共享收件人回执防止跨适配器或重启后重复问候。关系估计不会授予发消息权限；不确定的发送不会自动重试。

## 记忆与恢复

入睡时固定上一段清醒期间形成的有来源记忆 ID。现有记忆写入模型分批整理选中记忆，每批可以返回多条结果：合并相关记录、拆分独立主题，并分别保留不相关的信息。每条输入都必须被结果引用；漏掉来源、引用无效、无新证据提高置信度或超出输出预算时，整批拒绝保存。每批结果原子写入，原始记忆保留；新记录作为带来源事件引用的模型解释存储。同一周期不会递归压缩这些结果，不同批次之间不进行合并。进度、剩余记忆 ID 和失败状态持久化；中断或结果不确定的模型调用需要显式重试，不自动重复。设置显示整理周期进度和重试控制。某批记忆整理失败不阻塞作息调度。

独立且带版本的 `genesis_sleep` 和 `genesis_qq_sleep_inbox` 存储域归属于现有生命身份和写入租约。备份时与生命数据、来源 Session 一起保存。已初始化记录丢失、身份不符、损坏或写入不确定都会明确报错。禁用睡眠保留历史，不会删除 QQ 消息正文或 Session 日志。管理备份或恢复前先停止运行时。

会话横幅仅读取包含 Life 模式标识的轻量作息状态；打开新会话或历史会话时，不会为横幅请求完整生命状态或扫描其他在线会话。

## 验证范围

本地最小冒烟使用真实存储，覆盖边界采样、节假日豁免、临时唤醒、保持清醒和重启连续性。包级类型检查覆盖宿主、QQ 适配器与客户端。真实决策及记忆模型响应、OneBot 投递和浏览器渲染交互仍需部署验证。
