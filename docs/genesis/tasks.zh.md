# Life 与工作区任务

[English](tasks.md) | 中文

## 模式

工作区 Genesis Web 组合将 Life 设为新会话的默认模式。Life 会话共享一个身份、情绪状态、长期记忆和已学工具，同时保留独立上下文。标准、PTC、极简和创造会话使用原 Harness 行为，不接收生命上下文或工具，不产生生命观察，不运行记忆、情绪、兴趣评审，也不进入生命能力历史。经过认证的逐回复记忆操作仅在参与生命模式的会话中可用。

隔离由 `awakening.lifePreset` 控制。未启用 awakening 的基础组合，或未限制预设的 awakening，保留所有会话参与的策略。已有普通会话的历史可能已经包含生命上下文；需要干净任务时请新建普通会话。原有生命存储和会话日志均保留。

## 安排工作

使用带 Life 与浏览器覆盖配置的[工作区启动方式](README.zh.md)。任务工具要求通过 `awakening.lifePreset` 指定独立生命预设；工作区注册表、预设注册表、默认模型、会话持久化及会话查询服务均挂载后，任务工具才可用。普通 Web 组合提供这些服务。通过现有模型设置配置实际可用的任务默认模型。

与其他[已学工具](awakening.zh.md)一样，通过 `learn` 教授 `genesis_tasks`。它不出现在初生工具列表中，学习不授予执行权限。学会后，AI 可以使用这些操作：

| 操作 | 输入与结果 |
| --- | --- |
| `catalog` | 返回已注册工作区的 ID、路径、名称，以及普通模式 ID 和可用性诊断。`default_mode` 可以是 Life；创建任务仍必须明确指定普通模式。 |
| `create` | 必须提供 `workspace_id`、`mode`、`request_id` 和独立完整的 `prompt`。返回 `task_id`、目标工作区和模式，以及提交状态。 |
| `list` | 必须提供 `workspace_id`；返回会话/任务 ID、模式和是否存在运行实例。`not-loaded` 不代表完成；请使用 `inspect`。 |
| `inspect` | 必须提供 `task_id`；返回轮次编号、执行状态、实际活动、请求来源、最近一轮助手文本和失败详情，不唤醒任务。 |
| `attempts` | 必须提供 `task_id`；分页读取各轮的开始/结束序号、时间和结束原因，结果正文保留在原始会话事件中。 |
| `cancel` | 必须提供 `task_id`；撤回尚未投递的提交并清除排队提示词，请求标识仍保留。已投递任务返回 `canceled: false`，请使用 `stop`。 |
| `stop` | 必须提供 `task_id`、控制请求的 `request_id` 和检查结果中的 `expected_turn`；持久暂停受管任务，并等待其所属工作结束。 |
| `resume` | 要求相同控制字段；重新检查权限后，在原会话和工作区中显式继续未完成工作。已完成或被操作者停止的任务会被拒绝。 |

`offset` 和 `limit` 在 `queryLimit` 内分页读取目录、列表或轮次记录。检查使用字符 `offset`、`result_chars` 和 `next_offset`；`resultChars` 限制完整响应，超限会明确失败。`state` 描述最近一轮；`execution_state` 还考虑后台工作和持久停止标记。轮次已完成但后台工作仍运行时报告 `background`；暂停任务在活动结束前报告 `stopping`，之后为 `stopped`。`result_complete` 要求执行已完成且无未结束活动，`next_offset` 表示仍有文本可读。运行中或失败的轮次可以包含部分文本。

每次分配都会在目标工作区创建不继承历史的普通会话，只传递明确提供的提示词，不复制对话、生命快照或记忆。任务模式不会默认回到 Life。提交保留调用方沙箱模式与部署默认值中更严格的限制，并保留拒绝审批请求的策略。既有工具策略、审批和操作者停止控制仍然适用。任务独立于发起会话，结束发起会话不会取消其工作。

重试相同工作时复用同一个 `request_id`。该标识属于单一生命，跨会话与重启有效。`create` 在创建会话前持久保存提交、原始请求方和权限上限。重试可向空白的预留会话完成投递，或创建尚未建立的会话，沿用相同任务和消息 ID。它重新检查当前工作区、预设及调用方访问权，并保留已保存、当前调用方、工作会话和部署权限中最严格的限制。不同输入、不可用配置和无法解释的会话历史均会明确失败。有匹配会话证据的旧任务仍可读取并去重。

`list` 包含尚未附加会话的待投递提交。`inspect` 在收件箱接纳前报告 `pending-delivery`，无需激活 Agent 即可读取冷会话的排队输入。`delivery` 字段表示已保存回执，与执行状态分开：`delivered` 要求会话持久化已确认，不表示任务完成。会话写入成功而回执写入失败时，重试会确认既有分配，不再发送一条消息。已消费或已取消的收件箱输入不会重新投递。中断的工作实例仍报告中断，本 API 不重放其行动。启动、检查和时钟不会派发待投递提交；继续投递须以相同输入显式重试 `create`。

## 停止与继续

控制请求使用自己的稳定 `request_id`。新控制的 `expected_turn` 必须匹配检查所得的 `turn`；过期请求在改变执行前失败。复用已完成控制会返回其回执和当前检查结果，不重复效果。尤其是重试旧停止请求不会停止后来的继续执行。控制仅适用于已记录的 Genesis 分配；普通会话继续使用工作区控件。

`stop` 在取消轮次前保存暂停状态。存在任务和子代理提供方时，还会停止所属后台任务并等待活动工作实例的驻留子代理树释放。确认结束后才报告成功，`taskStopWaitMs` 限制后台任务等待时间。无法确认停止时返回错误，并保持任务暂停。计划跟进及其他提供方拥有的活动须使用各自控制，剩余活动会阻止成功。暂停跨重启保留，拒绝内部唤醒和工具执行。工作区中真实的用户消息可以接管，Life 不能通过 `resume` 覆盖用户发起的停止。

`resume` 必要时加载原冷会话，保留上下文与目标工作区，并采用已保存、工作会话、调用方和部署权限中最严格的上限。它提交已记录的继续执行消息，要求工作实例先检查已有结果和外部回执。它不回滚行动，不保证外部效果恰好发生一次，不重新开启已完成工作，也不自动重试失败。已预留的恢复请求没有会话回执时，原请求重试和新继续请求均被拒绝：先检查已存进度与外部结果，显式停止以核对请求，再使用新的控制标识。启动和检查从不恢复工作。

## 存储与恢复

版本 1 的 `genesis_tasks` Storage Domain 共用生命写入租约，每项提交保存在一条原子记录中，包含可选停止状态与控制回执。`maxRecords` 统计提交及保留的控制回执，`maxStateChars` 限制完整任务记录，容量耗尽会拒绝接纳。待投递记录保留所提交的提示词，直至投递确认或取消后清除该副本，同时保留标识和归属。取消不会删除已有会话日志或消息。轮次历史来自会话事件；版本 2 的任务投影缓存从这些事件重建，无需转换会话格式。

备份须包含此存储域、工作区数据和会话存储，单独的生命状态备份不包含它们。损坏记录会拒绝加载，任务记录写入结果不确定时停止任务操作，直至核实后重新加载；已确认任务的会话缺失时不会自动重建。不含控制字段的已有记录仍可读取。旧运行时不能执行停止/恢复回执的约束，并可能拒绝新增字段；依赖这些回执的部署不要降级。

## 人工查看

打开左侧边栏的“Genesis → 委派任务”，分页查看受管分配。已认证只读页面分别展示投递和执行状态、轮次数及实际后台活动，无法确认的读取明确标注。页面不唤醒或重试工作，“打开会话”复用既有工作区导航查看上下文和操作者控制；已归档或不可访问的工作区不进入列表。

打开目标工作区的正常会话列表即可找到新会话，原有模式标签、对话历史和运行控制均保留。分配内容以带来源的 Life 通知出现，后续展示真实助手和工具输出。任务 ID 就是会话 ID，分配来源保留发起 Life 会话和请求标识。`inspect` 也能读取已注册且未归档工作区中的既有普通会话，拒绝 Life 会话及该集合以外的会话。

任务输出是带归属的数据，Life 需要自行判断如何使用；输出文本不能授予权限或覆盖操作者指令。完成状态表示工作会话的真实轮次结束结果，不独立证明答案正确。当前测试使用脚本模型验证真实 Loader 组合和持久化，不代表已验证真实模型提供方或桌面/浏览器兼容性。
