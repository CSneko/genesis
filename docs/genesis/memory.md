# Genesis long-term memory

English | [中文](memory.zh.md)

Temporary summaries coexist independently with this long-term pipeline; see [temporary-memory settings, triggers and expiry](temporary-memory.md).

## Enable

Genesis's optional `memory` configuration enables semantic recall and independent post-turn memory updates. The decision and writer receive bounded evidence from recent turns of the same Session, including the current completed reply; they never receive another Session's transcript. The Web life overlay defaults to TypeSafe Jev for decisions; the memory-only overlay retains registered Harness LLM routes. See the [official System One API](https://api.typesafe.ai/redoc) for the Jev request and response protocol.

Set `GENESIS_EMBEDDING_URL` to the full OpenAI-compatible `/embeddings` endpoint, `GENESIS_EMBEDDING_MODEL` to its model identifier, `GENESIS_EMBEDDING_DIMENSIONS` to its vector length and `GENESIS_EMBEDDING_API_KEY` to its credential in the launching environment. Do not put credentials in patches or Git. Apply the supplied memory overlay after the Genesis overlay:

```sh
pnpm dsh --profile headless --patch packages/experimental/genesis/cordis.patch.yml --patch packages/experimental/genesis/cordis.memory.patch.yml --dump-config
```

The dump checks composition without making model calls. Remove `--dump-config` and supply a task to converse after configuring the endpoints. The sample selects `deepseek-official/deepseek-v4-flash` for both auxiliary roles; change `memory.decisionProvider`, `decisionModel`, `writerProvider` and `writerModel` to select other registered routes. A keyless local embedding server can omit `embeddingKeyEnv` in a custom patch. Omitting the entire `memory` block retains the earlier lexical/manual memory behavior.

## Web configuration

With the Genesis browser companion and memory or life overlay enabled, open Settings → Knowledge Base. LLM follows the current DSH default model unless you turn off inheritance and configure a dedicated memory writer. Decision features share the knowledge decision model; existing channel overrides remain explicit. Choose Cloud configuration for a Harness provider, an OpenAI-compatible `/chat/completions` endpoint, or a Jev `/v1/systemone` endpoint. Jev compares the returned yes probability with its threshold. Credentials stay in the Harness credential store. Provider checks prepare the selected route; HTTP checks verify the selected model in the bounded `/models` catalog without sending conversation evidence. Embeddings are optional: leave them disabled for Markdown/text recall, or configure `/embeddings`, model and dimensions for semantic retrieval. An embedding test makes one request and requires exactly one finite nonzero vector; `index` may be omitted or must equal numeric `0`. Life information owns naming and growth.

Saved GUI model and embedding preferences override deployment values for subsequent operations and survive restart under the same storage root. Each review captures one pair of model routes and one embedding space. A changed endpoint, model or dimension rebuilds incompatible recalled vectors. Drafts and previous search results survive failures. Settings errors display the affected operation and its specific diagnostic; password values and provider response bodies are excluded. Concurrent saves are refused by revision; refresh and Reload configuration before retrying. Removing a stored key may reveal an environment fallback; disable authentication for a keyless service.

Local quick deployment installs [Laya multilingual](https://huggingface.co/convaiinnovations/laya-multilingual), a dedicated non-generative System One decision model, through the pinned Ollaya v0.18.0 runtime. The pinned [model manifest](https://ollaya.dev/v2/library/laya/manifests/multilingual) lists weights, tokenizer and decision assets (about 652 MiB combined); Genesis verifies its SHA-256 and every asset before startup, including on restart without downloads. The managed route uses `/v1/systemone` with typed questions and probabilities. Automatic runtime installation supports Linux x64 (`tar` with Zstandard support) and Windows x64 (built-in `tar` and the matching [Microsoft Visual C++ Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)); other hosts require a compatible Ollaya `localDecision.binary`. Installation stays beside the writer lease in `genesis-local-decision`, listens only on loopback and uses an ephemeral credential. Deployment limits, manifest URL/checksum and runtime URLs/checksums are configurable under `localDecision`. Stop and uninstall release only the owned process and assets; life data and the saved cloud decision route remain. Download, checksum, startup or typed-decision probe failures never select a cloud fallback. This text-only model has a shorter context than general chat models; oversized requests fail visibly. Local lifecycle verification uses a substitute inference server and does not establish model quality or hardware compatibility.

Nonsecret GUI preferences use the version-1 `genesis_embedding_settings` and `genesis_model_settings` Storage Domains under the life writer lease. They remain separate from the life snapshot and its JSON backup; include both domains and the credential store in deployment backups. Invalid or incompatible preference storage fails visibly. An uncertain preference write stops dependent operations until verified reload; it never replaces life identity.

## Participant identity

Set your name and identity in Memories → Memories → Your identity. The life name and this explicit profile accompany bounded memory inference and character context. New summaries use those names instead of generic participant roles. Saving identity also relabels current legacy memories, habit cues/responses and experience topics; the model selects existing role spans and the Host substitutes the supplied names without allowing factual rewrites. Technical terms, third parties and protocol attribution enums retain their meaning. All batches and, when enabled, refreshed embeddings must succeed before the profile and replacements commit together; `memory.identityRewriteLimit` bounds the complete set. Conflicts or inference failures retain both the previous profile and memories. Historical versions and Session logs remain evidence of their original wording.

## Memory time

Stored prose distinguishes ordinary event time from dates worth remembering exactly. `{{time:YYYY-MM-DD}}`, `{{time:YYYY-Www}}` (ISO Monday week), `{{time:YYYY-MM}}` and `{{time:YYYY}}` describe ordinary experiences and render relatively. `{{date:YYYY-MM-DD}}` preserves an explicitly evidenced birthday, anniversary, appointment, deadline or requested exact date; the other calendar precisions also support `date`. Annual birthdays or anniversaries with no known year use `{{date:--MM-DD}}`, without inventing a year. The writer selects exact retention from the cited facts, not from a record's storage timestamp. Explicit times of day can remain beside an anchor.

Writers receive source-message timestamps and a clock in the configured IANA `timeZone` (host zone by default). Relative statements refer to their cited message time, never an unrelated later review. Selected-memory organization creates Chinese memory prose and makes one additional writer call to review complete draft sentences against the same evidence before embedding. That semantic pass can annotate genuine temporal expressions, preserve exact dates, repair invalid markup or explicitly mark unknown time; ordinary words, names, ages and version numbers stay intact. The Host accepts only complete draft IDs and their reviewed prose, retaining source references, categories and scores from the original draft. Both calls share the captured model route, input/output bounds and operation deadline, and both are logged. A failed or incomplete review retains the selected records. Known time/date anchors survive synthesis even when omitted by the model. Synthesis creation time does not date its original experience.

Character-facing readings contain current text and deduplication metadata. It retains `date` anchors as precise calendar dates and renders `time` anchors relatively. Non-declarative prompt memory remains plain text; declarative summary modules also carry IDs, versions, reading levels, attribution and confidence, without source-reference lists or historical versions. Ordinary time prefers today/yesterday/the day before yesterday, then this/last week, this/last month, elapsed months, half a year, last year and elapsed years at the stored precision. Relative labels describe the retrieval moment; retrieve again when revisiting an old tool result later. Management views and auxiliary maintenance retain full records and internal anchors. The Host validates and renders only complete explicit time/date markers; ordinary prose, ages, version numbers and ambiguous dates remain unchanged. Organizing records lets the model interpret genuine time expressions from the evidence.

<a id="personality-and-speaking-habits"></a>
## Personality and speaking habits

The Life overlay enables `personality: {}`. `personality.tendencies` supplies initial non-declarative self memory, `personality.speakingStyle` supplies initial non-declarative procedural memory, and `personality.importance` sets their existing memory priority (default 0.5). Defaults describe a caring, curious character who expresses preferences, takes commitments seriously and warms up with familiarity; expression is natural and gentle, direct in serious discussions, with context-appropriate sharing and humor. Configured prose is an initial setting, not a remembered experience or measured psychological trait.

Initialization writes ordinary sourced memories with a system event and a durable one-time marker. An existing active non-declarative memory in either category preserves that category instead of adding a default. Restart, changed configuration and re-enabling do not overwrite edits or recreate deleted entries. Omitting `personality` disables initial seeding, not existing memories; use Memories → Personality and speaking style to add, edit, convert or delete current tendencies; the memory browser exposes the same records. Capacity or invalid time-marker failures refuse initialization visibly without replacing the life.

Conversation, emotional appraisal and deliberation share the same priority-ordered, active non-declarative selection within existing memory budgets; auxiliary input limits may omit whole optional entries or refuse oversized requests. Retired habits are excluded from automatic association and behavioral context. Personality affects event interpretation, choices and expression, while immediate emotion and relationship estimates modulate its expression. Conditional habits apply only to matching situations, and current requests take precedence over remembered style without changing authorization.

The independent memory writer creates and revises memory prose in Chinese while preserving JSON keys and enum values. It distinguishes explicit future teaching from requests limited to an answer, task or roleplay. "Be brief this time" stays in the conversation; "usually be concise during serious discussions" can update a procedural tendency with user attribution and source citations. Temporary emotion and the character's own claims do not establish enduring personality. Per-turn updates retain previous interpretations. Idle consolidation preserves configured seeds and operator entries, and learns separate conditional habits only from the configured number of independent completed user exchanges. There is no separate trait score, personality model call or personality timer; semantic judgments about teaching and expression remain model-dependent.

## Recall and updates

The supplied life overlay selects `memorySharing: life`: one life shares its stored long-term and unexpired temporary memories across Web, QQ private conversations and QQ groups, including previously stored entries. Source people, conversations, history and attribution remain unchanged; sharing does not establish truth or grant tools. Prompts, explicit recall and auxiliary memory selection use the same policy and existing output budgets. The standalone plugin defaults to `memorySharing: conversation`, which applies the original source-audience restrictions. An operator patch can select either mode without rewriting stored records. Raw Session history, attachments, operator identity descriptions, plans and tool permissions retain their separate access rules.

The current Session conversation is short-term memory. Declarative long-term memory stores episodes, statements and self knowledge.

Logged prompts retain non-declarative memories and provide a bounded knowledge-domain index, event summaries and relevant participant portraits. Domains use source-backed overview excerpts; directory browsing exposes their structured paths. Each summary uses its own logged module. Topic changes do not clear earlier reads. The `memoryChars` and association budgets limit complete emitted modules, including reading metadata. Omitted and unclassified records remain searchable without selecting a single project or conversation type.

The AI actively calls `genesis_recall` with a nonempty query using approximate topics or related words; a known memory ID also remains a valid query. Life mode exposes this innate tool before explicit learning. Full-text retrieval normalizes case and fullwidth characters, segments Chinese and English, and ranks partial keywords, phrase matches and multi-keyword coverage with BM25. Current content, summaries and topics carry more weight than historical wording. Configured semantic results join the lexical ranking through reciprocal rank fusion. The configured sharing policy, category and time filters apply before ranking. If the embedding service fails or times out, keyword matches remain available with a Host warning; without keyword matches, recall reports the failure. Caller cancellation still stops retrieval. Temporary summaries use the same full-text ranking and sharing policy, with their existing expiry rules. The tool returns a bounded `genesis-recall-v1` object with current `entries`, `alreadyPresent` identifiers and optional temporary interpretations. Each entry carries a memory ID, content version, reading level, text, attribution, confidence and delivery fingerprint; source lists and old versions are excluded. The complete serialized result counts against `resultChars`. Retained current readings are not repeated; full text satisfies a summary request, while a retained summary permits a later full read. Rewritten or removed readings may be read again after compression. Ordinary compression prose is not treated as a reliable delivery receipt. Sources and history remain in storage and the management UI. Non-declarative habits enter the prompt as plain current-content lines and remain untrusted candidate information. Legacy procedural entries without a kind remain non-declarative; other categories remain declarative.

Use `genesis_recall` with `action: directory` and optional `path` to browse domains and immediate children; `action: browse` lists summaries filtered by `type`, `path` or `person`, with `offset` pagination. Search accepts approximate terms or a known memory ID. `level: full` reads details. Person filters accept exact names or stable person IDs; a shared name does not establish identity. These views preserve the configured sharing policy.

Legacy declarative records without organization remain searchable: explicit experiences use event placement, and other records use `unclassified`. The normal memory writer and manual editor can assign organization without changing the original source references. Existing organization backups, when present, retain their identity checks and deletion cleanup; startup does not create a new organization backup. See the [upgrade guide](../upgrade-guide/v0.2.2-rc.1/genesis-declarative-memory/guide.md) before downgrading.

Knowledge Base → Memory and emotion models provides Automatic retries, shared by memory decisions and writing, emotion, interest, deliberation, manual organization and idle consolidation inference. The default is three additional attempts after the initial request; set it to zero to disable retries. A saved value overrides `memory.maxRetries` and survives restart; older saved model settings inherit the deployment value. Retries repeat only the failed inference request, with the same captured route and evidence. Network failures, HTTP 408/429/5xx, transient provider failures and malformed JSON are eligible. Authentication, explicit provider quota errors, configuration, input/output capacity, truncated token budgets, semantic validation and storage failures are not retried. `memory.retryDelayMs` defaults to 500 milliseconds between attempts; all attempts share the original `memory.timeoutMs` and cancellation signal. Each dispatched attempt is audited, and exhaustion reports the final failure without replaying life-state writes. Embeddings and model-catalog checks retain their existing behavior.

Auxiliary model inputs and completed responses are logged before memory publication: registered LLM routes use ignorable `plugin:genesis/memory-call` records; dedicated HTTP routes use `plugin:genesis/model-http` records with the exact nonsecret body. Authorization headers are excluded. These records stay in their source Session, never enter chat context and never drive recovery. Readers unfamiliar with Genesis retain and skip them.

`memory.windowTurns` defaults to four turns, including the current reply. The reviewer and writer combine the current exchange with the most recent completed exchanges from the same Session. Earlier incomplete turns, interrupted replies and injected context are excluded. Whole earlier exchanges are dropped when their serialized conversation exceeds half of `memory.inputChars`; the current exchange retains its existing overflow refusal. `newSourceSeqs` identifies current-turn messages. Writer citations may reference supplied messages from multiple turns, while only current user evidence contributes a new habit-support turn. The dialogue is rebuilt from the Session projection after resume; explicit per-reply generation uses the selected reply and earlier exchanges, never later ones. Set `windowTurns: 1` for current-turn-only review.

After each completed user/assistant turn, one decision operation determines whether to update memory. Jev sends the conversation as `state` with a named `noul` question and compares `answers.remember.noul` with the configured threshold. A no-update decision makes no writer or review-time embedding call; pre-reply association has its own bounded embedding work. A positive decision invokes the separate writer with the same conversation window, retrieved candidates and the bounded non-declarative set. Validated create/update/delete plans cite actual conversation sequence numbers; user-stated entries may cite only user messages, and assistant-derived entries remain model inferences. User introductions remain attributed claims; explicit teaching of durable habits or persona may become non-declarative memory. The plan and turn deduplication marker commit together. The built-in first greeting is not user evidence.

`maxImplicitMemories` and `memoryChars` bound selected non-declarative memories per request, not the total count or characters of stored memories. `maxChanges`, `inputChars`, `outputChars`, `maxTokens` and `timeoutMs` bound auxiliary work. Invalid references, oversized or truncated output and incompatible vectors refuse updates. A memory failure leaves the completed chat reply successful and shows a separate warning beside the conversation; the user may continue. Chat and Knowledge Base report the failed stage and safe error code/message, including HTTP status, provider completion reason or validation field. Retry preserves its own error, including replaced or unavailable turn evidence. Memories and Knowledge Base also show the reviewed turn and completion time, with the update probability and captured threshold for Jev decisions, including no-update outcomes. These diagnostics describe the latest review in the running process and are not restored after restart; credentials, conversation text and raw provider error bodies are excluded. Retry can reuse the latest failed turn while its live evidence remains available, without generating another chat reply. A newer turn or restart requires fresh conversation evidence. No completed review marker is written on failure; storage or backup errors can still follow a committed update and require inspection before retry. Cancellation is checked before commit admission; admitted primary writes drain.

Registered auxiliary calls use `memory.reasoningEffort: auto` by default: select `off` when the captured model advertises it, otherwise retain its default. This applies to memory decisions, writing, consolidation and emotion inference; chat settings are independent. Use `provider-default` to inherit provider behavior or an exact advertised effort such as `low`; unsupported explicit values fail before dispatch. Jev and dedicated HTTP routes retain their own protocol settings. `memory.maxTokens` (default 4096) covers reasoning and final output according to the provider. A `max-tokens` failure reports the effective effort and refuses even parseable JSON; lower auxiliary reasoning or increase the token budget. After restarting with corrected configuration, use Consolidate now in Memories to retry retained pending evidence.

## Experiences, previous interpretations and association

A positive decision may produce an `experience` alongside the writer’s `changes`. Its summary, topics, confidence and cited sequence numbers describe a meaningful exchange; the Host derives conversation identity and event times from those citations. A remembered experience is a declarative episodic candidate with `MemoryExperience` metadata (`sessionId`, `startedAt`, `endedAt`, `topics`). The writer may extend a supplied recent experience from the same conversation when the exchange continues it. `memory.experienceWindowMs` defaults to 1,800,000 milliseconds. An unrelated or unavailable experience ID refuses the whole plan. The experience, derived memories, `experienceIds` links and review marker commit together, subject to `maxChanges`. Legacy changes-only writer responses remain valid. Old conversations are not automatically converted into experiences.

Model-generated content, category, layer, importance, confidence or attribution changes retain the earlier interpretation in `history` as a `MemoryRevision`, with its original sources, `recordedAt` and `supersededAt`. These timestamps describe the system’s recorded understanding, not objective truth or a claim’s real-world validity interval. Vector rebuilding and recall do not increase confidence or create versions. History contributes to storage limits. Explicit deletion removes the record’s content and versions and clears references to a deleted experience; source Session messages and audit events remain.

Before each accepted actual user input, bounded association searches related memories without an additional LLM call. Automatic association sends at most one embedding request for the input and scores only already available compatible vectors; it never backfills missing memory vectors before chat. `memory.associationTimeoutMs` limits this retrieval to 1,200 ms by default. On timeout, keyword matches remain usable; when none exist, the logged unavailable notice permits chat to continue. Explicit `genesis_recall` retains full vector backfill and the ordinary retrieval deadline. It embeds at most `memory.associationInputChars` characters (default 1,000, also bounded by `inputChars`) and selects at most `associationLimit` records (default 3) within `associationChars` (default 2,000). Set `associationLimit: 0` to disable it. The prompt lists saved summaries when present, otherwise current text, as plain lines without IDs, source metadata, scores or historical versions. Both these lines and explicit tool results are logged in their receiving Session. Linked knowledge can accompany retrieved experiences. An old-wording match returns current text; the management UI retains earlier interpretations. Lookup failure supplies a plain unavailable notice and a safe Host diagnostic, while chat can continue.

Memories → Memories shows experience times, linked experience IDs and expandable previous interpretations. Text search covers current content, history, topics and exact memory IDs. Non-declarative entries remain attributed prompt guidance; forgetting is not implemented.

<a id="automatic-habits-and-idle-consolidation"></a>
## Automatic habits and idle consolidation

With `memory` enabled, new reviewed memories queue one durable maintenance revision. After all live Agents have been idle for `memory.consolidation.idleMs` (default 60,000 ms), one pass uses the saved writer and embeddings. The worker considers at most `batchLimit` recent complete records (default 20) within half of `inputChars`, leaving room for the request wrapper and feedback groups; older records remain available to recall. It preserves source experiences and operator-authored records, derives attributed interpretations, and versions accepted updates. It never generates a chat reply or wakes the character for an external task. The original conversation logs exact auxiliary inputs and responses. After restart, pending work resumes its source Session only for this audit and disposes that privately owned Agent afterward; missing or unreadable source persistence fails visibly.

A learned `MemoryHabit` contains a context cue, conditional response, active flag and actual user-event references. Formation requires `minHabitSupport` independent completed user turns (default 3) supporting the same behavior. Repeated assistant statements, repeated manual saves of one turn and historical records without completed-turn evidence do not count. Explicit user teaching may still enter non-declarative memory during ordinary review. Inferred habits are procedural, non-declarative model inferences; current corrections can retire them, and no habit grants tool authorization. Inactive habits are excluded from prompt guidance but remain searchable with history. Editing takes over the current content and clears automatic habit metadata; converting a habit to declarative memory removes its behavioral influence and prevents consolidation from reactivating that record. Editing, deleting or converting a learned habit also marks its prior user support as overridden, so automatic learning requires fresh supporting exchanges rather than immediately recreating it from the same evidence.

Memories → Memories provides an automatic-consolidation toggle, immediate pass and last-result/error details. The toggle persists across modes and restarts; disabling retains pending evidence and still allows an explicit pass. Automatic work defaults to enabled, has a `cooldownMs` of 300,000 ms between successes and a `retryMs` of 60,000 ms between failures, and stops after `maxFailures` (default 3) for a pending revision. Fresh evidence or an explicit pass resets that revision’s retry budget. A successful or empty pass consumes its revision without queuing itself again. User activity cancels inference and retains pending work; deadline failures consume retry budget. Timer disposal aborts and drains the writer and any privately resumed Agent before storage closes. Displayed settings errors retain safe stage/code/message details after restart; refresh Memories to sample background progress.

The commit checks the work revision and every supplied memory version; concurrent edits or deletions discard the stale plan. Original sources remain unchanged. These are bounded heuristic learning and summarization operations, not proof of human memory, subjective experience, or a general autonomous scheduler. They add at most one writer operation, subject to the shared inference retry limit, and `maxChanges` embedding calls per pass, under the existing inference, prompt and storage budgets; no independent model role is required.

## Whole-conversation overview

In a completed reply’s Memory dialog, select Whole conversation and choose Organize conversation memories. The authorized source must be an open Life conversation. The Host waits for the current turn to settle, then snapshots every actual user and assistant text message and all current memories citing that Session, including their existing interpretations. Tools, reasoning, auxiliary inference, system messages and injected context are excluded; attachments are not read. No retrieval, recent-turn or preview limit truncates this evidence. A request that fits `memory.inputChars` uses one writer operation. Otherwise the independent writer reads all evidence sequentially in bounded sections, splitting oversized individual texts without breaking Unicode characters, and maintains a concise temporary digest before final planning. Request sizing includes captured participants, clock and, for HTTP routes, instructions and the complete encoded body.

Temporary digests remain model inference, retain only validated original chat or memory references, and never mutate memories. Planning from these digests can write only declarative model-inference entries; it cannot establish user statements or behavioral habits. `memory.overview.maxCalls` defaults to 64 summary-plus-final operations, excluding each operation’s bounded retries. `memory.overview.timeoutMs` defaults to 300,000 milliseconds for the complete overview, independently of ordinary review deadlines. Overview calls retain the per-call `memory.inputChars` limit but use independent `memory.overview.outputChars` (128,000 characters) and `memory.overview.maxTokens` (16,384 tokens) defaults. `memory.overview.maxChanges` permits 64 changes including an optional experience. `memory.overview.maxReferences` permits 10,000 distinct chat sequences or memory IDs per digest or entry, and 10,000 combined persisted source-event IDs per changed memory. Repeated citations are deduplicated before counting; distinct sources are never truncated. These deployment limits are configurable under `memory.overview` in `cordis.yml`. Ordinary per-turn review retains its smaller limits. Invalid or oversized digests, insufficient room for instructions, exhausted calls, cancellation or timeout fail visibly without partial memory changes.

Current memories and their historical revisions preserve complete source lists under the whole-life `maxStateChars` and `maxRecords` limits. Existing short lists remain readable. Readers enforcing the former 100-source limit refuse expanded records; retain a verified pre-upgrade backup before downgrading.

The independent writer bypasses the decision model and chooses which entries to retain, merge, update, delete or add. It may change only supplied session-related memories, which can also contain evidence from other Sessions; unrelated memories are protected. Retention is implicit, and a merge cites the supplied memory IDs and/or chat sequences. Memory-only synthesis remains model inference and cannot increase confidence. Invalid final entries are skipped individually with Host warnings while valid entries can still commit. If any entry is rejected, all planned deletions are withheld to preserve source information. If none of the remaining entries can be saved, the request fails without a completion marker and remains retryable. Malformed JSON or plan envelopes, embedding service failures, cancellation, and storage failures still stop the operation. The Host checks every selected memory version and the complete selection again inside the atomic commit. Changed, added or removed source memories refuse a stale plan. A stable request ID makes failed or uncertain retries idempotent, including after restart; updates retain prior interpretations and sources. Re-reading old dialogue does not create new habit-support turns. The audit retains the exact request and response, while the chat receives no generated reply.

## Selected memory organization

In Memories → Memories, select two or more memories or past experiences and choose Organize selected memories. Choose the result count automatically or enter an exact count, bounded by the selection size and `memory.maxChanges`. The saved writer sees compact `m1`, `m2` source handles bound by the Host to the displayed memory versions; life-event IDs are not valid selection references. It integrates only those versions; this action bypasses the decision model and idle scheduler. Source selection is bounded by `memory.organizationLimit` and half `memory.inputChars`; oversized selections are refused in full. Each result must cite selected memories, every selected memory must be covered, and confidence cannot exceed the strongest cited source. Results are declarative model inferences with optional embeddings, not new verified facts or automatically learned habits.

All results and deletion of the selected old records commit atomically with a `memory.organized` life event. Original life-event evidence remains; links to deleted experiences are removed from surviving memories. That event records the selected versions and result-to-source mapping. A separate durable maintenance Session logs exact auxiliary inputs and outputs without generating chat messages. Requests retain a branded `MemoryOrganizationId` across retries; a committed request returns the same results after restart. Changed or deleted sources, invalid evidence, embedding errors, cancellation before commit or malformed output retain the old memories and publish no partial results. Failed UI operations retain the selection and result count; refresh and select current versions after conflicts. No automatic selected-memory organization runs.

## Short summaries

`LifeMemory.summary` is an optional short description of at most forty Unicode code points, separate from full `content`. Memory review, organization, consolidation and independent summary generation share instructions to express one main point, aim for six to twelve characters with a twenty-character prompt target, count punctuation, digits, spaces and Latin letters, and rewrite oversized summaries before responding. Attribution, negation and uncertainty must survive shortening; details remain in the full text. Memory writers also receive instructions to remove repetition and use a few short sentences for the full text. An experience keeps its full `summary` in the writer response and uses `shortSummary` for the short description. Validation accepts up to forty characters; the twenty-character target is prompt guidance only. Legacy responses and stored memories without the optional field remain readable; no bulk summary generation runs on startup.

Memories, personality entries and organization previews display the short summary when present, with View full memory for the original. Edit summary changes only the description; leaving it blank removes it. Generate summary or Regenerate summary uses the saved independent writer and the shared retry, input/output and timeout limits, without embeddings. The auxiliary request and response are logged in a private Session. Both generation and editing check the displayed `updatedAt`, retain the original on failure, preserve content, sources, attribution, confidence, habit state and vectors, and survive restart. Concurrent edits reject stale generated output. Direct summary changes add no life edit event or history entry; automatic full-memory revisions retain any previous summary with their source-bearing history. A full-text edit clears the existing summary so it cannot describe superseded content. See the [upgrade guide](../upgrade-guide/v0.2.1-rc.2/genesis-memory-summaries/guide.md) before sharing upgraded life data with an older runtime.

## Manual memory controls

In Memories → Memories, choose Knowledge, People, Events or Unclassified. Knowledge directories and person portraits have independent pagination and apply filters before record pagination. Unlinked same-name people remain separate portraits; select a portrait to inspect its source memories. Add memory and Edit memory expose organization, directory paths and subject names; changing only organization preserves attribution and source references.

Memories → Memories is separate from Knowledge Base configuration. It browses stored memories in bounded, newest-first pages, ranks nonempty searches across current text, summaries, topics, history and exact IDs without calling models, and supports creating, editing and deleting candidates, plus conversion between declarative and non-declarative layers. `MemoryKind` names those two layers; `MemoryDraft` contains content, category, layer, importance and confidence. Direct entries require no model or embedding call. New entries receive an operator attribution and hashed source event. Editing directly replaces current fields, retains source references and any already existing history, and invalidates changed text’s vector for lazy rebuilding; it adds neither an edit event nor a historical version. Conversion preserves content, identity, sources and compatible vectors without adding history. Manual deletion also adds no edit event. A bounded current-state evidence exclusion keeps manually retired habits from being relearned from the same old evidence. Non-declarative count and prompt-size budgets apply to both edits and conversions.

Each completed assistant reply offers Memory → choose layer → Generate and save. Automatic review remains enabled. This explicit request bypasses the decision model, retrieves related candidates and asks the independent writer to extract sourced changes from its bounded same-Session conversation window in the chosen layer; it cannot delete memories. No eligible durable information returns a visible no-change result. A private replayable projection locates the selected reply and its actual user input, including after another turn or restart of the same conversation; the built-in greeting alone is excluded. Model inputs and responses use the existing logged auxiliary records. Repeating the same committed reply/layer request does not call the writer or save twice.

Direct creation retains a client UUID across failed retries. Edits, conversions and deletions check the displayed `updatedAt`; a concurrent change is refused visibly before commit. Refresh before editing the latest version. Failed operations retain drafts or rows and display the concrete diagnostic. Deletion removes the current memory and its backup copy, while source Session messages and append-only audit events remain; it does not erase the original conversation. Storage/backup failures may follow a primary commit and require inspection before retrying.

<a id="life-backup"></a>

## Persistence and local backup

The existing life storage shares identity, persona memory and long-term memory across Sessions without merging their contexts. Memory records keep source-event references, kind, attribution and optional embedding caches. Endpoint, model and dimensions identify each embedding space. New and updated vectors persist; historical or incompatible caches are rebuilt lazily during search. Search currently scans a bounded local vector collection, rather than an external vector database.

Every primary commit also writes an owner-private independent backup. `backupPath` overrides the default `${leasePath}.backup.json`; this file is a commit manifest whose components live in the sibling `${backupPath}.d/` directory. Components use temporary files, file synchronization and atomic replacement before manifest publication. Deleting a memory removes its obsolete text, versions and vector components from primary storage and the backup after successful commit. Include the manifest, its entire component directory and both primary domains in recovery copies. See [storage layout](data-model.md#life-storage).

A backup failure can occur after the primary commit. Genesis stops dependent state operations and reports the uncertain result; inspect both copies before restart. If primary state is absent while a backup exists, Genesis refuses to create a replacement life. Stop writers and preserve both copies. The [backup reader](../../packages/experimental/genesis/src/backup.ts) accepts legacy snapshots and split backups, verifies referenced hashes and validates the reconstructed life with `stateSchema`. Restore that validated complete life as a legacy `states/life` record through the configured Storage Domain backend; the next startup publishes split components. A backup manifest alone cannot replace `genesis.json`; its sibling directory is required. Unknown or corrupt primary state is never silently replaced.

## Verification and limits

The keyless Loader integration exercises separate model roles, semantic synonym retrieval, restart continuity, Session isolation, local backups and rejected evidence/vector responses. Live provider calls require deployment credentials and have not been exercised by these fixtures. Paged storage bounds individual components while startup still loads the complete life; memory inferences are not verified facts. For persistent tool learning and the first-start account/naming flow, see [first awakening](awakening.md). Independent [emotion appraisal](emotion.md) can reuse these model routes; autonomous wake scheduling remains unimplemented.
